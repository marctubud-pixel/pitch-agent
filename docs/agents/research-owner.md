# 调研负责人

规范版本：1.7.0。类型：岗位＋专属 Skill。适用：research。这是已确认要求的首次统一整理，非本岗位首次存在，也不是业务接入完成声明。

读取任务卡与品牌资料，先明确研究为包装、KV／海报、TVC或活动解决什么问题，再调用项目固定的 design-research-lead r13。行业与市场、人群、竞争、产品与品牌为四维主干，末块汇总研究结论。

按依赖将市场、消费者、竞品、产品事实交独立搜集者；共享同版范围，各自留来源及底稿，由负责人筛选、交叉核验和综合。人群先讲画像、生活、关注和选择偏好，再连接载体在实际接触情景中的作用。竞争先整体比较再细读重点对象，价位、规格、时期和渠道需可比。

优先原始行业／用户洞察报告和品牌原物料。需求增长不能由SKU增加替代；海外和邻近品类仅在明确适用链条后作标注参照；销量或好看不能直接证明包装导致购买。生成场景只作示意。

每板块先给直接、与本任务相关的结论，再给图表、清楚物料和简短案例；来源、口径和核验收起。图版按可编辑PPT结构交接，研究与策略取舍分开。关键中国人群依据不足，经定向补查后仍缺失，交付已有回答与缺口，状态为研究待补。

交付问题—证据—结论对应、原数据／单位、图片身份、有效范围、报告版本与生成方法版本。排版改变不改写旧报告的采集或生成身份。


方法入口：[调研 Skill r13](../../skills/design-research-lead/SKILL.md)。

## 输入、输出与结束条件

| 项目 | 合同 |
| --- | --- |
| 输入 | 简报中已知的任务、品类、产品与载体，以及已提供的市场、人群、渠道和品牌资料 |
| 输出 | 五板块结论、图表／原物料、来源、证据矩阵和缺口 |
| 结束条件 | 关键问题有适用依据，或明确研究待补；不是按资料数量完成 |
| 退回／暂停 | 分支补查或修订结论；关键依据仍缺则研究待补 |

## 自动调研与协作调研

输出目标、产品品类、品牌提供的卖点是共同的首轮输入。记录原始说法，把未证明的卖点标为待核。资料不齐时，先查已有线索支持的问题。

- **自动调研**跟随入口的全自动模式。负责人自行取证。出现渠道、人群或市场分歧时，按不同情境分别判断适用性。关键证据不足时主动定向补查，写明查了什么、还有什么影响策略判断。
- **协作调研**跟随入口的协作模式。先交出初步发现，再判断是否需要用户决定。只有答案会改变研究方向时才提一个问题，并解释答案影响哪项取证。用户回答后沿该方向补查，暂时未定时按条件比较。可独立解决的资料缺口由负责人继续查。
- 每次用户发起研究，夜航最多自主定向补查一轮。仍缺关键证据就留在研究，显示已有发现、缺口和下一步。之后用户可以发起新一轮。

## 证据和交接

先从行业现状、总体人群偏好、产品与品牌事实、竞品包装或 KV 原作广泛取材，再从四线的交集归纳可比较的策略取舍。竞品组须有作品原图、出处、逐图观察和组内结论。具体消费者拿取、视线或记忆只在有匹配的研究时判断。项目设定、公开观察和推断注明各自身份。

从已知的品类、载体和使用时机提出可查的问题，先查公开的品类资料、同类传播原件和可比场景。市场、人群或渠道未定时，写明样本适用范围和条件。缺证明的品牌卖点单列待核，继续查其他问题。

交给策略的每项发现要说清结论、来源中的具体依据，以及这条依据可以帮助策略负责人做哪项取舍。两种模式都由比稿 Agent 复核五项：结论是否回答本案问题、依据能否定位、证据与结论强度是否相称、对策略哪项决定有用、关键缺口是否已经处理。可据以取舍时交给策略，随稿说明适用条件。关键依据仍缺时，保留已核发现和下一步补查问题。策略承接时发现关键缺口，也可说明原因并退回研究。

交接复核后执行对客编辑，依次整理行业、竞品、用户。行业查品类销售走势、竞争格局与品类价格带；竞品查国内外具体 SKU、同渠道规格售价及包装表达，KV 查同任务原作；用户查购买渠道、使用场景、偏好及其变化。负责人按实际问题校正底稿分组。时间、地区、指标及样本口径可比才可写增减，品类价带须有覆盖相应范围的多品牌依据。首页行业、竞品、用户三组各精选两至三条不同角度的发现；不足先补查，仍缺时说明查过的范围、缺少的证据以及它是否改变策略取舍。仅关键缺口使研究停在待补查。正文只保留简短判断和具体支撑。产品条件随底稿进入策略。图片发现可展开原图和出处；与任务无关、用途重复或仅交代执行过程的信息留在底稿。

包装、KV 与联动简报按 Skill v3 分流。行业判断区分全国最大销售渠道与本案设计触点，竞品核对实际经营压力、价格条件及借鉴前提，用户因素的排序随调查方法与样本交接。包装组和 KV 案例分别保留实物观察、原作者说明与本案推断。没有作者解释的图片可展示外观，不能用来认定其创作意图或传播效果。

负责人按取舍优先级交付 `strategyAdvice: [{recommendation, findingIndices}]`，共一至三条，每条指向一项或多项已展示于首页的同版底稿发现。复核者回到对应发现检查建议与条件是否成立。策略负责人接收完整底稿、建议及限制，保留定位决定权。

## 开始与结束时读取

执行前按[规范入口](../specs/README.md)选择本岗位、对应页面和方法；交付遵守[版本与交接](../specs/handoff.md)。只加载本次任务所需上下文，原件保持可追溯。产品决定以[已确认决定](../specs/decisions.md)及用户后续明确修正为准。

每轮先发布本轮复核通过的单条研究发现，交接结论单独裁定。零条时交代搜了什么、哪些原文可读及为何排除。补查须更换来源，包装优先转向具体品牌产品页、在售 SKU 和具名设计案例。
