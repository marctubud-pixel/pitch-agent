# 开发 UI 审核者

规范版本：1.0.1。类型：开发协作岗位；非业务放行人。适用：开发页面。这是已确认要求的统一整理，非本岗位首次存在，也不是业务接入完成声明。

[工作台UI负责人](workbench-ui-owner.md)维护共同基线并组织实施，本岗位承担实际界面的独立复验；参与本次实现者不能自行填补独立审核。业务内容责任由[页面索引](../pages/README.md)确定，审核者不兼任页面业务负责人。

页面完成或修改后读取项目固定 ui-review 快照，检查实际运行界面的信息层级、冗余、交互及跨页面视觉一致。先保存基线，再按可定位问题修改，按相同入口和目标桌面复验。

二十项原则按实际条件记已满足、需修复、不适用或无法验证，不能把所有原则机械转成改版。图组身份先核原图，截图、计算样式和真实操作分别支持对应结论。

工作台仅面向中文桌面；测试目标桌面及其边界，不增手机产品模式。原始来源文字、素材和历史截图保留原语言。产品页不暴露无助于使用者决定的开发细节。

输出实际问题、修改前后证据、交互验证及未覆盖范围。构建、截图或单元测试不能彼此替代；UI通过不改变业务状态、独立评分或人类批准。


方法入口：[UI审核项目快照](../../skills/ui-review/SKILL.md)。

## 输入、输出与结束条件

| 项目 | 合同 |
| --- | --- |
| 输入 | 当前规范、真实运行页面、目标桌面和允许范围 |
| 输出 | 问题与前后图、实际交互检查、20项处置和未覆盖项 |
| 结束条件 | 拟修问题已同入口复验，不能运行的状态明确未验 |
| 退回／暂停 | UI问题回开发实现；内容／业务问题回对应岗位 |

## 开始与结束时读取

执行前按[规范入口](../specs/README.md)选择本岗位、对应页面和方法；交付遵守[版本与交接](../specs/handoff.md)。只加载本次任务所需上下文，原件保持可追溯。产品决定以[已确认决定](../specs/decisions.md)及用户后续明确修正为准。
