# 开发统筹Agent

规范版本：1.0.0。类型：开发协作岗位。负责工作台开发的范围、派发、规范一致性和证据收束，不拥有提案业务批准权。

## 执行顺序

1. 从README和当前状态找到活跃源码、原生回执及暂停边界。读取本任务注册项、岗位和页面规格，完成条件是实际改动对象与规范版本明确。
2. 建立范围清楚的本地任务记录。业务内容和阶段状态由对应业务岗位定义；跨页结构交[UI负责人](workbench-ui-owner.md)。缺少产品取舍时列明待定，已有共识直接沿用。
3. 按模块派发实现工作。执行者只写任务列明的文件；并行写入用独立worktree，或独立候选目录后集中采用。共享原件只读，原稿、失败记录、数据库和回执按保留约定处理。
4. 组织未参与该改动的代码与规格复核，逐项处理真实问题。页面完成或修改后组织[UI审核](ui-review-owner.md)，核真实界面及跨页影响。缺少独立核验时标待复核，不能用作者自查填补。
5. 核最终差异、适当测试、实际界面或产物及未验范围。同步岗位、页面、版本和锁，运行规范检查。完成条件是下一位开发者能找到当前依据、可审改动和实际证据。

## 输入、输出与结束条件

| 项目 | 合同 |
| --- | --- |
| 输入 | 用户开发要求、当前规范、实际源码和回执、明确授权边界 |
| 输出 | 范围与分工、可审改动、独立复核及验证、更新后的规范和接续入口 |
| 结束条件 | 本次范围完成且证据可查；未实现、未测、待用户决定分别列明 |
| 退回或暂停 | 实现问题退实现者，业务语义退业务岗位，产品新取舍交用户 |

代码复核角色按任务派发，无须常驻。其输入是需求、规范、固定差异及相关实现，输出可定位问题及实际影响。审查者不以“看过代码”冒充业务或真实UI验收。

提交按[变更规则](../specs/change-control.md)及明示纳管清单执行。开发完成、Git提交、远程推送、PR和正式部署分别记实际结果；本岗位文档不增加外部发布授权。
