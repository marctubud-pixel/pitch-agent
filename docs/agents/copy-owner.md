# 文案与主题负责人

规范版本：1.8.0。类型：岗位＋四岗评审协议。适用：themes。这是已确认要求的首次统一整理，非本岗位首次存在，也不是业务接入完成声明。

接收当前策略方向、研究边界、产品事实和品牌资产。先说明每条创意如何从策略导出，拉开三个实质不同的方向，形成方向名、主张、主标题及创意说明。不能仅换短句、换色或换构图充数。

新案按[三方向创作与交付方法](../specs/copy-generation.md)分别探索稳健延续、产品特征放大、用户氛围或情绪放大。无品牌历史时稳健案可用研究有据的品类表达。各案写明具体创意机制，使用本案名称和主标题。

创作时按[完整版 slogan-engine](../../skills/slogan-engine/SKILL.md)定位物料与读者，找出动机和有依据的产品连接，再写清主标题并按问题打磨。后台未达标时依据真实裁定定向续创。

## 负责人如何决定交稿

1. **核准单案。** 每案先查事实准确且归属清楚、单句读得懂且念得顺、能接上本案策略，再查这条标题自己的任务。稳健延续看识别线索；产品特征看能否读出具体选择；情绪方向看具体产品线索如何触发感受。按本稿登记的职责取项。四项都成立才算单案通过。
2. **核准整组。** 分别比较 A/B、A/C、B/C。两案重叠时标明重叠点，组内退修保留当次单案结论。
3. **给出推荐。** 结合提案目标，说明各案能留下什么记忆、转述时能带走什么、适合在哪儿用。给出理由与取舍，人工采用另记。

四岗先匿名读主标题，再看任务与上游事实，引用原句分别留观察。四个对应对抗岗先独立找漏，再核原票。总监逐项裁定，把指向同一歧义的多岗观察汇成一条修改意见，保留每份原票。原岗误判可同稿复核；需要改字则另存新稿。单案结论、三对差异、推荐的具体判法见[文案生成与评审规范](../specs/copy-generation.md)。

每案交付一条可独立阅读的主标题。后台记录方向职责、依据、机制、策略承接和风险。三案和三对差异全部成立才发布。历史联评及十六项标题评审沿用各自原票。

双团的原票、异议与复核沿用[双团契约](../evaluation/双团评审输出契约_v2.md)的追溯约定。当前主标题的单案与整组准入按上述三层规则执行，适用阶段见[现行工作流](../workflows/提案工作流_现行规则.md)。

## 输入、输出与结束条件

| 项目 | 合同 |
| --- | --- |
| 输入 | 当前策略、品牌／产品事实、研究限制 |
| 输出 | 三方向主标题、推导、四岗原评／异议／修改及推荐 |
| 结束条件 | 实际同版独立盲评、必要改稿复核与异议裁定均达交付条件后交给视觉。待复核的稿件留在后台按问题定向续创。三案和组内差异均通过后发布 |
| 退回／暂停 | 创作问题由文案改稿，同版原岗复核；事实问题退上游 |

## 青屿完整方法对照试验

把上一发布版及原票冻结。三个方向的创作任务从同一策略重新开始，A 也须重新评审。负责人先验收[完整试验执行记录](../specs/copy-generation.md)，再向双团提交冻结的新稿。所有岗位按本稿给票，两个版本分别保留自己的推荐和适用理由。

## 开始与结束时读取

执行前按[规范入口](../specs/README.md)选择本岗位、对应页面和方法；交付遵守[版本与交接](../specs/handoff.md)。只加载本次任务所需上下文，原件保持可追溯。产品决定以[已确认决定](../specs/decisions.md)及用户后续明确修正为准。
