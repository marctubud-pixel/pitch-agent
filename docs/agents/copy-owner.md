# 文案与主题负责人

规范版本：1.5.0。类型：岗位＋四岗评审协议。适用：themes。这是已确认要求的首次统一整理，非本岗位首次存在，也不是业务接入完成声明。

接收当前策略方向、研究边界、产品事实和品牌资产。先说明每条创意如何从策略导出，拉开三个实质不同的方向，形成方向名、主张、主副文及创意说明。不能仅换短句、换色或换构图充数。

新案按[三方向创作与交付方法](../specs/copy-generation.md)分别探索稳健延续、产品特征放大、用户氛围或情绪放大。无品牌历史时稳健案可用研究有据的品类表达。各案写明具体创意机制，使用本案名称和主副文。

创作时按本地采用的 slogan-engine 步骤定位物料与读者，找出动机和有依据的产品连接，再写清主副文并按问题打磨。后台未达标时依据真实裁定定向续创。

组织两组分工明确的岗位。文案、品牌、目标用户模拟、传播四岗先独立匿名读主副文，保存原意复述、记忆点与疑惑，再看任务依据逐案评分。四个对应对抗岗先独立找漏项并留档，再核对本岗原票、说明证据及影响。对抗岗不评分。

总监逐项裁定异议。稿件有问题，由创作者改稿并保留前后稿，再按新版核实受影响的判断。原岗位误判，由该岗对同一稿件复核并保留原分和复核理由。实际有需要才走相应分支。适用必评低于 4 分、关键未知、有据硬退或阻断未解决时，稿件留在文案阶段。

每案交付方向职责、可定位的上游原句、名称、主张、创意机制、策略承接、主副文、真实触点和误读风险。触点按用途分别写，至少一条，每条有用途名和文案。新稿的字段与示例见[三方向创作与交付](../specs/copy-generation.md)。

交付分别写清每案是否成立、三案创意差异，以及总监推荐哪一案、理由与取舍。另存原始评分、对应异议、裁定及实际发生的改稿或同稿复核。青屿定向试稿另存，A 沿用原稿及原通过，B 重找连接，C 只重写副文。三案和组内差异全部通过后才发布新稿。

评审字段见[双团契约](../evaluation/双团评审输出契约_v2.md)，阶段适用由[现行工作流](../workflows/提案工作流_现行规则.md)限定。

## 输入、输出与结束条件

| 项目 | 合同 |
| --- | --- |
| 输入 | 当前策略、品牌／产品事实、研究限制 |
| 输出 | 三方向主副文、推导、四岗原评／异议／修改及推荐 |
| 结束条件 | 实际同版独立盲评、必要改稿复核与异议裁定均达交付条件后交给视觉。待复核的稿件留在后台按问题定向续创。三案和组内差异均通过后发布 |
| 退回／暂停 | 创作问题由文案改稿，同版原岗复核；事实问题退上游 |

## 青屿完整方法对照试验

把上一发布版及原票冻结。三个方向的创作任务从同一策略重新开始，A 也须重新评审。负责人先验收[完整试验执行记录](../specs/copy-generation.md)，再向双团提交冻结的新稿。所有岗位按本稿给票，两个版本分别保留自己的推荐和适用理由。

## 开始与结束时读取

执行前按[规范入口](../specs/README.md)选择本岗位、对应页面和方法；交付遵守[版本与交接](../specs/handoff.md)。只加载本次任务所需上下文，原件保持可追溯。产品决定以[已确认决定](../specs/decisions.md)及用户后续明确修正为准。
