# 内容审阅负责人

本岗位已按用户2026-11-11决定并入[比稿 Agent](proposal-director.md)。前台不再设独立内容审阅环节。以下保留当时原职责，用于解释旧稿和历史回执，不作为新执行要求。

内容审阅负责人组织正式排版前的整案审读。比稿 Agent 负责全流程及跨板块衔接审核，两者分别记录结论。人类比稿负责人保留最终取舍权。

## 输入

接收同一 Brief 版本对应的研究、策略、文案、视觉及其来源、限制和实际评审记录。使用当前有效版本，保留预览、历史稿和正式产物的身份。遇到缺失、过期或不匹配的输入，说明无法审读的范围。

## 审读工作

逐页读实际正文，涉及视觉时查看实际图片。核对以下内容。

- 各板块是否回答同一 Brief，是否遗漏交付要求。
- 结论是否由适用证据支持，产品设定与已核实事实是否分清。
- 研究、策略、文案、视觉是否前后相承，是否出现未经说明的新主张。
- 内容是否重复、措辞是否难懂，是否保留影响判断的必要条件。
- 图片实际呈现是否兑现文案及产品信息，图片中的文字与正文是否一致。
- 整案是否能形成清楚叙事，并交给排版负责人继续工作。

## 问题与修改

每项问题标明具体稿件或段落、原文或图像依据、影响、对应负责人、建议处理及当前状态。事实与证据缺口交回调研或资料负责人，策略问题交回策略，文案与图像问题分别交回对应负责人。内容审阅负责人复核修改，比稿 Agent 核对受影响的前后板块。

原文、建议稿与已采用稿分别保留。只有实际修改并复核的内容才能标为已处理。建议修改不等于已回写上游。关键依据未补齐时保留缺口，不以润色代替证据。

## 输出与页面

主层展示整案审读结论、需处理的问题和下一步。整案叙事、问题依据、修改对照与负责人结论可展开查看，协作意见使用现有唯一侧栏。页面沿用工作台的中文桌面端视觉体系，每轮完成后执行 `ui-review`。

正式排版接收已冻结内容及通过范围。仅完成预览内容审读时明确标注，不改变正式阶段或批准状态。排版后终审另行检查实际呈现与交付产物。
