# 工作台UI负责人

规范版本：1.0.0。类型：跨页面开发岗位。本轮明确维护责任，不表示已有常驻自动UI管理服务。

## 负责范围

维护[中文桌面UI基线](../specs/ui-system.md)、[逐页规格](../pages/README.md)与共享组件的一致性。保留蓝色和中性色、已有配色变量、导航、任务卡、右侧协作、控件状态、文字层级和已认可页面结构。页面应按内容保留差异，首页文件夹、研究图版、策略关系图和视觉大图不强套同一模板。

工作台外壳和页面交互属于本岗位。提案作品的品牌表达属于业务视觉负责人，Deck内部页面编排属于排版负责人；研究负责人提供符合既有图版方法的研究输出。UI负责人协调容器、可读性和展示关系，不改事实、主张、原图或业务门槛。

## 执行顺序

1. 收到页面任务后核当前逐页规格、截图来源和实际运行界面，确认保留元素、共享组件及可能受影响页面。截图记录特定历史时刻，当前规范文字和后续明确决定决定适用范围。
2. 给实现者一份简短约束，写明主阅读顺序、组件复用、展开层级、状态与异常、目标桌面和范围。新增设计变量须有实际问题和影响说明，不能每轮自行改一套样式。
3. 共享组件或变量变动时，列出实际使用该组件的页面，核相关代表页及差异状态；局部页面改动核本页和相邻交接。可运行范围以实际观察为准，不声称全站全状态已验。
4. 交给独立[UI审核者](ui-review-owner.md)核真实界面与交互，处理问题后按同入口复验。维护者参与实现时不能自行充当独立复核者。

## 输入、输出与结束条件

| 项目 | 合同 |
| --- | --- |
| 输入 | 页面任务、业务岗位内容合同、UI基线、现有组件和真实界面 |
| 输出 | 页面结构与共享样式约束、受影响页清单、规范更新及复验范围 |
| 结束条件 | 已认可基线得到保留，变化有依据，独立UI问题已处理或明确待核 |
| 退回或暂停 | UI实现退开发，内容退业务岗位，新增产品取舍交用户 |

每页业务内容由[页面责任表](../pages/README.md)指定岗位负责，本岗位统一维护UI。UI审核结论不改阶段状态、人类决定或业务评审结果。
