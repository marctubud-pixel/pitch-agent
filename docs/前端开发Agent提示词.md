# 前端开发 Agent 提示词

你要为“提案工作台”开发产品化前端。先阅读以下文件，再检查当前代码和真实 API：

- `AGENTS.md`
- `多线调研工作台_开发说明_v0.3.md`
- `docs/前端开发指南_提案工作台.md`
- `tools/workbench/README.md`
- `tools/workbench/ui.html`
- `tools/workbench/server.mjs`
- `tools/workbench/project.mjs`
- `tools/workbench/store.mjs`

## 目标

把现有用于验证流程的本地页面，整理成清楚、易用、可追溯的提案工作台。优先改进项目列表、项目概览、研究成果和证据、阻断项、任务执行记录、阶段交接与图片观察的浏览体验。保持工作台服务同源运行，默认入口为 `http://127.0.0.1:4181`。`tools/auto-layout` 的 4180 端口是独立工具，不要混入或破坏它。

## 工作方式

1. 先确认当前目录、未提交变更和项目约定。不要覆盖用户已有工作。
2. 阅读指南及实现，盘点真实页面、服务路由、请求字段、响应数据和业务状态。不要凭文档摘要猜 API。
3. 先给出简短页面结构和组件拆分，然后直接实现，不要停下来等待批准。
4. 沿用现有技术栈，除非现有结构无法完成目标；若确需改变依赖或部署方式，先说明原因并选择改动最小的方案。
5. 所有业务状态以服务端返回为准。前端不得伪造模型身份、核验结论、评分、负责人签收、放行记录或任务完成状态。
6. 修改请求遵守 `commandId`、`expectedRevision` 和幂等重试规则。冲突时提醒用户刷新并核对，不要静默覆盖。
7. 对不可用能力显示明确状态和服务端原因。当前搜索、图片生成、创意评审、后续阶段执行和完整排版交付存在未接通部分；不要伪造可用流程。
8. 区分排队、运行中、待核对、失败、成功但未放行和过时版本。任务提交成功不代表成果通过。
9. 确保键盘操作、语义化控件、文字对比度和窄屏布局。保留历史版本只读查看，并提醒未保存内容。
10. 完成后启动本地服务并在浏览器验证主要页面和实际 API 操作。不要新增或运行自动化测试，除非用户另行要求；可以做必要的手工运行验证。

## 交付

完成可运行的前端实现，并在最终回复中总结页面与交互变化、主要修改文件、手工验证步骤和仍受后端限制的能力。不要声称未验证的功能已接通。
