# 在本机使用夜航提案台

## 启动与入口

在仓库根目录使用 Node 24.13.0，首次执行 `npm run setup:frontend`、`npm run setup:workbench`，以后从 `npm run dev` 启动。打开[夜航提案台](http://127.0.0.1:4420/)。服务需要保持运行。历史七阶段页面可以从[经典工作台](http://127.0.0.1:4420/?classic)和[青屿终审](http://127.0.0.1:4420/#/p/qingyu/proposal/delivery)进入。

普通开发服务准备已登录的 Codex CLI 0.167.0，并在 Codex 设置中选定支持本次任务的模型。视觉阶段需要当前账户可用的图像生成能力；研究使用允许的网络检索。请求会使用本机 Codex 的登录身份与额度，提交前请确认简报及附件适合交给所选模型。排版使用 Chrome 或已安装的 Playwright Chromium。开发机可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器。

桌面应用从「菜单 → 模型与 API」选择模型。完成仓库依赖安装和 build 后，运行 `desktop/nightflight/build.sh "$PWD" /新的目录/夜航提案台.app` 构建。第三个参数 `review` 创建独立数据目录的体验版，使用 Application Support/OnePitch/Review/projects。设置构建环境变量 NIGHTFLIGHT_PYTHON 可指定这台 Mac 已安装依赖的 Python。

## 亲自跑一次

1. 进入首页，填写需求、添加参考材料，选择协作方式后启动。顶部日志显示实际进度；阶段正文和附件可以从工作区查看。
2. 简报先整理任务卡。研究先用简报中的品类和任务检索，逐条说明结论、来源依据和对策略的用途。研究足以支持策略时才交接，证据不足时留在研究补查。包装、KV 及联动的策略交一页，含核心策略、人群洞察、品牌角色、主张与三项动作和各载体触点，三项待测指标留在后台原稿；其他类型沿用研究结论、方向交叉点、策略发力点。文案分别探索稳健延续（可用有依据的行业惯例）、品牌或产品特征、用户氛围或情绪。四岗先匿名读主标题，再看任务和方向依据。单案检查三项共通要求及一项本方向任务，推荐理由交代记忆点、复述和场景。四个对抗岗先独立找漏，再核对应原票。总监逐条裁定，需要改稿或同稿复核时才进入相应流程。完成后可分别查看单案是否成立、三案差异和推荐理由。协作模式下由你选择其中一个方向生图，自动模式会为三个方向各生成一份概念图。
3. 到视觉阶段，打开并检查概念图。选择「采用并写逐页稿」，夜航读取本版材料和原图，再用 DeepSeek 按 [ppt-slide-script v4](../../skills/ppt-slide-script/SKILL.md) 编稿。版式可下载逐页稿、材料包和调用记录，也可按「按逐页稿排版」生成成品。「采用并整理材料包」提供供手工编稿的材料。「采用所选稿并排版」在已配置模型时依次完成编稿和排版。
4. 版式显示 PPTX 预览、翻页和「逐页稿与材料」，可查待补项和各页原图出处。夜航使用 Deck Studio 按原稿页序生成可编辑 PPTX 和每页实图。逐页稿排版的终审由逻辑、措辞、美术三岗审读，直修后另存成稿，复检全览和改过的页。查看改稿回执和全览后选「验收这版」。必改项还在时可按责任阶段发修改意见。版式的精确改字格式为「第 8 页，把『原文』改为『新文』」。
   核验导出时用本机演示软件独立打开下载的 PPTX，核对中文字体、页数和图文。隔离运行的 LibreOffice 可通过 `FONTCONFIG_FILE` 读取本机 CJK 字体。
5. 在交付文件中下载 PPTX。回到历史项目可再查看。原件、当前产物、历史版次与操作记录在 macOS 默认保存到 `~/Library/Application Support/PitchAgent/nightflight`；其他系统默认保存到 `~/.local/share/PitchAgent/nightflight`。如需指定项目数据位置，请在启动前设置 `NIGHTFLIGHT_DATA`。跨分支使用同一数据目录时，结束旧服务后再启动新版。备份本地提案时请连同目录内文件一起保存。Git 版本回退用于代码和规范，提案存储需要单独备份。

## 两种模式如何调研

交代输出目标、品类和产品卖点即可开始。任务若是“某品类的新年海报”，即使渠道和人群还未定，研究也能先比较真实节日传播。品牌自述与已核实的产品事实分别记录。

- **全自动模式**用已有资料展开研究，遇到未定的市场或渠道时，分别说明不同场景的证据和适用范围。出现关键证据缺口会自主定向补查。
- **协作模式**也先查。负责人先给出已有发现，只有会影响研究方向的产品决定才请你回答一个问题。回答后继续取证，也可以暂不确定，按条件继续比较。缺的是可以自行查到的资料时，负责人会自主补查。
- 每次发起研究最多自主定向补查一轮。两种模式都用同一标准交接。有可核出处、结论能支撑策略取舍时继续。关键缺口仍在时可在研究详情查看原因，再补材料或启动新一轮。

## 从已有项目重试研究

打开原项目，在工作区进入「研究」。项目已完成简报且当前没有阶段在运行时，可填写「补查重点」，也可留空。若项目已走到后续阶段，点击「从研究重新开始」，继续使用原 Brief 和任务卡，旧版研究及后续产物归入历史。启动后看研究详情中的结论、依据和策略用途。如果仍缺关键证据，或策略明确退回，在研究页查看原因并点击「开始补查」。

## 开发边界

- `apps/workbench-preview/nightflight` 来自用户指定的「提案台-夜巡」源码。首页、启动、四栏工作区、日志、对话、资料和交付沿用这套页面与交互。下载目录中的原型 ZIP 保留原始演示与计时器。夜航首页展示的项目和进度应从本机服务读取。
- `tools/nightflight/start.mjs` 提供回环地址和同源文件服务；`service.mjs` 维护阶段、人工采用、重试、版本记录、附件与下载；`codex-runner.mjs` 装载对应岗位规范，调用本机 Codex 并核本次生图会话及文件；`layout.mjs` 复用原 Deck Studio 1.7 和可编辑 PPTX 导出。模块详细验证见对应的 `.test.mjs`。
- 本机综合试用只代表实际可见产物及其核对范围。原有 47 页包装和 50 页 KV 是另两份已验工程案例。外部 API 单案成本、单独付费模型、公网服务器、私有访问和域名验收见[上线计划](nightflight-launch-plan.md)。

## 主视觉候选

协作模式按选定方向生成三稿，自动模式三个方向各生成三稿。各方向独立推荐。查看原票后采用，排版只接收各方向采用的图片。

视觉负责人先看本项目上传的 PNG/JPEG，结合本版三案文案分配参考图。每案要有一张能支撑本方向的主参考，辅助图最多两张，每张说明借鉴的部位和本案用法。品牌标志或官方 VI 可登记为共用素材。实际生图输入按方向保存文件名、SHA-256 与用途，修改稿优先带回该方向的上版原图。附件较多时每次看最多四张，逐图登记后才分派。每次生图也最多附四张，容量不足时先保留主图、共用品牌图及上版原稿，记录暂缓的辅助图。

包装与 KV 可以从纯文字 Brief 开始。当前方向缺合适的主参考时，执行器按方向检索公开候选，取回并读取原图，保存检索词、来源页、图片地址及原图 SHA-256。稳健方向看品类表达，产品方向找能解释卖点的画面，情绪方向看人物行为与场景。自动搜得的参考包须经视觉、品牌、用户、传播四岗看原图，各岗两维逐项达到 4/5，对抗核票及裁定通过后才生成主视觉。未过的包保留原票并按具体缺口换词补查。只有可核的出处才能支撑销量或热度判断。找不到合适原图时会指出缺口，可重试或从对话区补图。自动模式检查三案，协作模式检查所选方向。

在视觉详情点击方向查看参考原图，展开「评审与说明」核对所借部位、本案用法和公开来源。包装同类对照、创作用参考以及采用的主视觉分别保存。采用后，版式读取同一版资料并生成预览与可编辑 PPTX。

桌面海报按实际主参考的五项观察生成借改指令。评审与说明会列出实际成图未兑现的借改项目。全自动三案还核对代表稿的视觉差异，未拉开的稿件保留原图并退出自动推荐。

包装评审先匿名看候选单图，再从本项目上传的 PNG/JPEG 中核对可用同类商品，使用原图与同序缩图评审。可在项目资料中加入同类包装正面图；缺少有效对照会在评审里列为待补。评审与说明按稿保存盲读、四岗原票、改图位置和待查资料。缩图使用本地 Python Pillow 生成。

### 研究结果与竞品原图

首轮从行业、人群一般偏好、产品与品牌、同任务竞品展开。复核按观察对象校正分类。行业看品类的走势、格局或价格带，竞品看具体商品和作品，用户看购买行为、使用场景和偏好。每组优先精选两至三个不同角度，首次缺项时定向补查。研究页每条显示短结论和依据说明，展开竞争发现可核对各张包装或 KV 原图、观察与来源。图片保存在本项目。缺少本地购买行为证据时说明适用边界。定点复验可以在重新研究的请求中指定 `researchOnly: true`，结果通过后人工点击「进入策略」恢复自动流程。

已通过而停在研究检查点的项目可以用 `research_digest` 操作按当前编辑规范重出摘要。请求携带最新 revision；复用本版核实发现和竞品原图，成功后回到原项目查看。

### 包装和 KV 的 PPT 排版

在 Brief 或上传的品牌规范中，可逐行写「品牌主色：#285747」「辅助色：#C09551」「品牌 Logo：品牌.png」「标题字体：宋体」。上传同名 PNG 或 JPEG 后，标志会随可编辑 PPTX 一起导出。色值、字体与文件名应来自本项目资料。工作台按逐页稿选择页型；可比较的同源数据可以进入原生图表，人群观察与竞品资料分别呈现。资料不足时，逐页稿记录实际页型、缺件或回退原因。
