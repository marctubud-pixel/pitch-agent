# 在本机使用夜航提案台

## 启动与入口

在仓库根目录使用 Node 24.13.0，首次执行 `npm run setup:frontend`、`npm run setup:workbench`，以后从 `npm run dev` 启动。打开[夜航提案台](http://127.0.0.1:4420/)。服务需要保持运行。历史七阶段页面可以从[经典工作台](http://127.0.0.1:4420/?classic)和[青屿终审](http://127.0.0.1:4420/#/p/qingyu/proposal/delivery)进入。

准备本机已登录的 Codex CLI，并在 Codex 设置中选定支持本次任务的模型。视觉阶段需要当前账户可用的图像生成能力；研究使用允许的网络检索。请求会使用本机 Codex 的登录身份与额度，提交前请确认简报及附件适合交给所选模型。排版使用 Chrome 或已安装的 Playwright Chromium。开发机可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器。

## 亲自跑一次

1. 进入首页，填写需求、添加参考材料，选择协作方式后启动。顶部日志显示实际进度；阶段正文和附件可以从工作区查看。
2. 简报先整理任务卡。研究先用简报中的品类和任务检索，逐条说明结论、来源依据和对策略的用途。研究足以支持策略时才交接，证据不足时留在研究补查。策略按研究结论、方向交叉点、策略发力点交接。文案分别探索稳健延续（可用有依据的行业惯例）、品牌或产品特征、用户氛围或情绪。四岗先匿名读主标题，再看任务和方向依据。单案检查三项共通要求及一项本方向任务，推荐理由交代记忆点、复述和场景。四个对抗岗先独立找漏，再核对应原票。总监逐条裁定，需要改稿或同稿复核时才进入相应流程。完成后可分别查看单案是否成立、三案差异和推荐理由。协作模式下由你选择其中一个方向生图，自动模式会为三个方向各生成一份概念图。
3. 到视觉阶段，打开并检查生成的概念图。采用会记录本版图片身份并启动排版。也可按界面提示提出修改。生成失败时，先查看具体错误，再决定重试。
4. 包装与 KV 可在新建页展开“提案结构”指定类型及额外委托，也可默认按简报识别。采用视觉稿后，版式从当次简报、研究、策略、文案和采用图按客户页序填稿。详情的“逐页稿与材料”可查缺件、看来源、按真实页码定位。其他类型及无法归类的旧输入沿用原排版。排版按正文实测容量分页，把本次稿件的原图字节和可编辑文字写入 PPTX。工作区逐页预览读取同一次编译保存的 Deck。终审读取本版文件的页序、文字及图片对象数。当前排版不输出逐页渲染图，报告会注明页级视觉审查待完成。审读使用本次 Codex 模型；正式独立五岗评审和人类签收另行记录。
5. 在交付文件中下载 PPTX。回到历史项目可再查看。原件、当前产物、历史版次与操作记录在 macOS 默认保存到 `~/Library/Application Support/PitchAgent/nightflight`；其他系统默认保存到 `~/.local/share/PitchAgent/nightflight`。如需指定项目数据位置，请在启动前设置 `NIGHTFLIGHT_DATA`。跨分支使用同一数据目录时，结束旧服务后再启动新版。备份本地提案时请连同目录内文件一起保存。Git 版本回退用于代码和规范，提案存储需要单独备份。

## 两种模式如何调研

交代输出目标、品类和产品卖点即可开始。任务若是“某品类的新年海报”，即使渠道和人群还未定，研究也能先比较真实节日传播。品牌自述与已核实的产品事实分别记录。

- **全自动模式**用已有资料展开研究，遇到未定的市场或渠道时，分别说明不同场景的证据和适用范围。出现关键证据缺口会自主定向补查。
- **协作模式**也先查。负责人先给出已有发现，只有会影响研究方向的产品决定才请你回答一个问题。回答后继续取证，也可以暂不确定，按条件继续比较。缺的是可以自行查到的资料时，负责人会自主补查。
- 每次发起研究最多自主定向补查一轮。两种模式都用同一标准交接。有可核出处、结论能支撑策略取舍时继续。关键缺口仍在时可在研究详情查看原因，再补材料或启动新一轮。

## 从已有项目重试研究

打开原项目，在工作区进入「研究」。项目已完成简报且当前没有阶段在运行时，可填写「补查重点」，也可留空。若项目已走到后续阶段，点击「从研究重新开始」，继续使用原 Brief 和任务卡，旧版研究及后续产物归入历史。启动后看研究详情中的结论、依据和策略用途。如果仍缺关键证据，或策略明确退回，在研究页查看原因并点击「开始补查」。

## 开发边界

- `apps/workbench-preview/nightflight` 来自用户指定的「提案台-夜巡」源码。首页、启动、四栏工作区、日志、对话、资料和交付沿用这套页面与交互。下载目录中的原型 ZIP 保留原始演示与计时器。夜航首页展示的项目和进度应从本机服务读取。
- `tools/nightflight/start.mjs` 提供回环地址和同源文件服务；`service.mjs` 维护阶段、人工采用、重试、版本记录、附件与下载；`codex-runner.mjs` 装载对应岗位规范，调用本机 Codex 并核本次生图会话及文件；`layout.mjs` 复用原 Deck Studio 1.7 和可编辑 PPTX 导出。模块详细验证见对应的 `.test.mjs`。
- 本机综合试用只代表实际可见产物及其核对范围。原有 47 页包装和 50 页 KV 是另两份已验工程案例。外部 API 单案成本、单独付费模型、公网服务器、私有访问和域名验收见[上线计划](nightflight-launch-plan.md)。

## 主视觉候选

协作模式按选定方向生成三稿，自动模式三个方向各生成三稿。各方向独立推荐。查看原票后采用，排版只接收各方向采用的图片。

视觉负责人先看本项目上传的 PNG/JPEG，结合本版三案文案分配参考图。每案要有一张能支撑本方向的主参考，辅助图最多两张，每张说明借鉴的部位和本案用法。品牌标志或官方 VI 可登记为共用素材。实际生图输入按方向保存文件名、SHA-256 与用途，修改稿优先带回该方向的上版原图。附件较多时每次看最多四张，逐图登记后才分派。每次生图也最多附四张，容量不足时先保留主图、共用品牌图及上版原稿，记录暂缓的辅助图。

若当前要绘制的方向缺主参考，视觉阶段会提示缺哪一案。通过工作区对话发送补充图和方向说明，再点重试。此处补的图片仅作为视觉资料；前序阶段仍用原 Brief 附件。自动模式检查三案齐全后开始绘制，协作模式只要求选定案齐全。此次接入使用项目实际上传的图，未新增联网搜图。

包装评审先匿名看候选单图，再从本项目上传的 PNG/JPEG 中核对可用同类商品，使用原图与同序缩图评审。可在项目资料中加入同类包装正面图；缺少有效对照会在评审里列为待补。评审与说明按稿保存盲读、四岗原票、改图位置和待查资料。缩图使用本地 Python Pillow 生成。
