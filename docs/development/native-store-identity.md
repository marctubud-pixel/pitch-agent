# 数据库打开文件身份

规范版本：1.0.0。此接口为满足明确条件的本地工具核验SQLite实际打开的文件，不是业务执行授权、通用恢复协议或跨平台证明。默认`openStore(file)`保持原语义，旧数据库、审计和来源记录不自动升级。

## 接口与适用条件

内部调用`openStore(file,{openedFileProof:true})`只支持已实际验证的Darwin环境。进程须由受控工具独占文件描述符生命周期，构造的同步区间没有其它worker或native代码并发开关普通文件描述符。当前专用接管控制器必须使用PTY并将此连接作为干净进程的第一native store；已有连接或缓存不追认。

DatabaseSync构造前，标准0/1/2描述符均须有效，3及以上不得已有普通文件描述符。构造后、PRAGMA及WAL/SHM打开前，必须只有一个新增普通文件描述符，且标准描述符身份不变。native模块以私有WeakMap绑定它的实际fd/dev/ino及关闭状态，不按路径、lsof文字或调用方回调猜测归属。

`assertNativeOpenedFileIdentity(store,{dev,ino})`检查真实持有的描述符，要求仍为原普通文件且与调用方固定的目标身份一致。调用方的目标身份必须来自其受信范围；任意传入一个数值元组不是授权。关闭、描述符失效、实际inode变化、无原生证明均拒绝。平台、现有描述符或归属不明时停止，不退回“同路径即同数据库”。

## 原边界继续成立

此断言不替代native durability与read-admission私有身份、完整snapshot/revision/semantic、任务/政策/方法、原件读取、CAS、未知停止或人工门禁。新接管仍须精确绑定其指定的案例及原创建/确认记录，不能恢复已经丢失的旧进程token，不能改写原创建或确认时间。

普通store、现有HTTP服务及旧source reader没有因新增接口自动获得文件证明。若调用方没有显式采用并满足条件，须继续注明原路径身份边界，不能发布全范围physical验证或App可写资格。当前公开HTTP请求不接受此选项；页面不增加此开发设置。

## 证据与限制

原独立反例在自有新库中把路径恢复为inode A、让真实SQLite句柄保留在inode B；路径stat与store私有路径字符串曾错误通过。修后相同正确拒绝断言通过。独立23项只签上述Darwin和独占条件，不宣称解决恶意进程内任意FD操纵或全部平台问题。

根四项子进程回归纳入`test:core`：默认无证明、受支持干净打开与close、路径/实际句柄分离、额外普通描述符保守拒绝。非Darwin核不支持分支，不计作成功打开正例。测试仅用独立新空SQLite；主案接管及后续模型调用仍按其各自原回执确认。
