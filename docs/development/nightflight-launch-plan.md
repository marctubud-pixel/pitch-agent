# 夜航提案台改造与上线计划

2026-11-15。Marc 选定「提案台-夜巡」作为下一版前端参考，产品在原型内显示为「夜航提案台」。默认入口已接入原型 UI、本机 Codex 运行和可编辑 PPTX。下一节点为 Marc 亲自提交首份试跑提案，核正文、实际生成图与下载体验，随后再进行单独的外部 API 验收与公网部署。见[夜航本机使用说明](nightflight-local.md)。当前可用基线是两个本地工程案例，包装 47 页、KV 50 页，原件、可编辑 PPTX 和终审结论见[验收记录](../../status/current.md)。

## 原型审阅

本机原件为下载目录「提案台-夜巡」的 `proposal-workbench-source.zip`（SHA-256 `2a5add2ebb4f829a752576c8b0a1302d13916aee1a0283d90719fbe33ff35b8d`）和 `proposal-workbench-standalone.html`（`3c45cdcf3f3f9d9701fd7311e090d6e138925ba4544e5719d2877d90bc7b1a3e`）。已在本机浏览器打开首页和简报入口，并查阅压缩包内 README、组件、数据和模拟层。

用户只面对一个主理人。首页讲清交付预期，简报入口收需求和参考，四栏工作区同时摆出主理人、任务、提案阶段、文档。顶部黑色日志呈现经过，侧栏对话处理补充和选择。白纸、细黑线、衬线标题与表示正在工作的橙色构成这套原型的视觉语言。工作台采用新风格后，提案作品仍按各自品牌和现有排版合同输出。

| 原型部件 | 实装时的数据和动作 | 验收情景 |
| --- | --- | --- |
| 首页、StartScreen、附件 | 接现有项目创建、Brief 原件登记和任务卡确认；保留文件身份和读取状态 | 上传后刷新，仍能打开同一原件，区分已上传、已读取和已确认 |
| Workspace、LogBar、ChatPanel | 对接项目快照、作业、真实执行记录和人的决策；主理人对应比稿 Agent，评审岗位分别留原票 | 等待、失败、恢复、退修都有实际原因；同一采用动作重复点击只形成一次决定 |
| 七阶段、DetailSheet | 将原型 copy、final 映射为现有前端 themes、delivery 等阶段入口；保留项目概览、资料、历史和交付入口 | 逐阶段能找到原稿、负责人、版本和下一步；青屿正式版式缺件时仍显示等待 |
| Slide、文档、比稿资料库 | 接同版 Deck、真实项目索引、页图和下载；用项目及版次标识关联附件 | 包装与 KV 分别显示 47、50 页；下载的两份 PPTX 与验收 SHA 一致；退出再登录仍找到旧版 |

原型以 React、TypeScript、Vite 构建。`src/sim` 用计时器驱动进度，文件上传记录名称，localStorage 恢复本浏览器的演示，演示菜单可以跳到完成。迁移先复用展示组件和布局，再把每项操作接入当前应用服务。演示模式可单独保留。工作模式须遵守当次授权、三方向交付、人类节点与独立终审；原型里的单次选方向、固定 12 页和完成动效均由真实项目状态替换。

## 实施顺序与验收

| 顺序 | 工作和负责方 | 何时可以进入下一步 |
| --- | --- | --- |
| 1 · 新界面本地并排体验 | UI 负责人在 apps/workbench-preview 内先接首页、简报、工作区，再接详情、资料库、历史和交付。分 PR 合入，保留旧入口作对照；确认新样式后同步页面规范、截图及版本锁。 | 在真实桌面浏览器体验一条完整操作路径；七阶段、等人采用、空态和错误状态均能定位。复用两份已验收成品做本地读写与下载回归。每轮按 ui-review 留证。 |
| 2 · 接文本和图片 API | 后端负责人复用既有适配器。选服务商、模型、可外发的测试材料和单案预算；服务端注入密钥。先各跑一次最小请求，再从新 UI 提交一份新 Brief。 | 收到可追溯的真实响应和图片，人工抽查研究来源、文案差异及成稿质量。走完采用、退修或放行、排版、审读和下载；记录耗时、调用量与实付成本。超时先查原请求，再决定能否重试。 |
| 3 · 历史项目与部署预演 | 后端负责人做私有项目目录。数据库记项目、权限、版本、阶段和文件指纹；对象存储放原件、页图、PPTX 和归档回执。保留原生执行所需的本地目录语义，云端读取后核验文件指纹。 | 用平台测试地址登录，换电脑查项目、打开旧版、下载核对；另一账号不能读取该项目。执行进程重启后可续查原作业，独立备份能恢复一个项目。测试环境实跑一次排版、字体、浏览器渲染和导出。 |
| 4 · 域名与上线 | 运维绑定选定域名、DNS 和 HTTPS，配置登录回调、私有下载、错误告警和备份；记录应用版本、数据库迁移及回退办法。 | 负责人从域名完成「新建 → 生成 → 查看 → 下载」，重启后旧稿仍可读，验证一次恢复与版本回退。再决定开放给哪些用户。 |

## 服务器和费用如何选

**当前建议**：先在本机完成 UI 和真实 API 测试，用实际每案的耗时、峰值内存、归档体积和费用选云规格。模型与图像调用按供应商报价另计，域名按注册和续费报价另计。以下是 2026-11-15 核查的候选方案，尚未采购。

- **只想在其他设备翻旧案。** 可以用静态前端托管加私有文件存储，电脑关机后仍能查阅。早期私人归档可先用受登录保护的只读项目索引；每次下载先核权限，发有时效的链接。Cloudflare Pages 提供免费计划；R2 Standard 每月有 10 GB-month 存储免费额度，另有读写请求额度，超额按量计费。私有提案和原图放受保护的位置，静态前端只发布应用资源。[Pages 限制](https://developers.cloudflare.com/pages/platform/limits/) · [R2 定价](https://developers.cloudflare.com/r2/pricing/) · [临时下载链接](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)
- **还要关掉电脑继续生成。** 需要在线后端和能持续执行长任务的进程。建议首发评估单台带持久盘的 Linux 云主机，运行 Node API 与可恢复的任务进程，先复用 SQLite 与受管原件目录，另做异地备份；用户增多后再评估独立数据库和多个执行器。这样能先在云端验证现有文件与导出合同。也可以选托管的付费计算和持久盘来降低运维量。[Render 持久盘](https://render.com/docs/disks)
- **免费后端适合短时测试。** Render 免费 Web 服务空闲 15 分钟会休眠，本地文件在休眠或重新部署后会丢失。若拿它试接口，把长期文件和数据库放到持久服务。完整提案的后台长任务优先在本机或常驻实例验证。[Render 免费服务限制](https://render.com/docs/free)

代码、规范与发布版本由 Git 管理。项目能否长期回看，验收依据是能从项目清单定位正确版次、恢复原件并打开下载，而不仅是能打开域名首页。
