# 存储保留与空间管理

本轮采用导航和索引，运行文件保持原位。源代码、正式测试和必要夹具随实现维护。目录名、时间或内容哈希相同都不足以证明可以删除。

| 位置 | 生成者与用途 | 保留及清理条件 |
| --- | --- | --- |
| `tools/`、`apps/` 中源码与测试、`tools/workbench/fixtures/` | 产品实现、正式测试和必要基准 | 保留；不按扩展名统一删除测试资产 |
| `.data/` | 持久数据库、版本、回执、资源 | 保留；SQLite 主文件、WAL、SHM 按同一数据库处理，活跃期间保持原位 |
| `.scratch/`、`.audit/` | 正式任务、候选实现、独立审查、失败和恢复证明 | 逐项判定，原件及有效证据保留；不能整体清除或隐藏源码 |
| 各系统临时 executionRoot | 当前两案及隔离测试运行 | 以实际 PID、锁、数据库与引用确认是否停用；当前两案全部保留 |
| `output/`、`sites/` | 交付候选、历史方案及展示工程 | 有效交付、独特素材和评审引用保留；转换副本只有在用途和替代件核实后处理 |
| `tmp/` | PDF、视频等转换或中间文件 | 先核对是否仍是唯一可用原件、是否被报告引用，再清理可再生成内容 |
| 项目内 `node_modules`、`.pnpm-store`、构建缓存 | 可重建依赖和缓存 | 确认无使用者、安装入口与成本后清理；本轮不清全局缓存 |
| `.git/` | Git 对象和已有自动快照 | 本轮保持不动，不改历史，不把忽略规则说成已经回收旧对象 |

实际大运行沿用至少 3 GiB 可用空间门槛，不为测试降低。磁盘读数受其他进程和交换空间影响，清理结果区分逻辑重复量、已删除文件占用和观测可用空间。

- Git 规则的实际检查见节点验证。它只证明 Git 路径匹配，未声称测得 Codex 平台所有未来快照行为或 Token 节省。已被追踪的文件需单独识别，普通清理不修改索引或历史。
