### 比稿 Agent 逐阶段统筹

人类比稿负责人拥有项目决定权，也是自动模式完成整案后的通知对象。比稿 Agent 对应早期“提案总监智能体”的统筹职责，组织任务拆解、派发、审核、退回修改及交接。

每个板块由对应负责人 Agent 执行。比稿 Agent 审核每个板块，检查它是否回应同一 Brief、承接有效上游结论，以及能否为下一阶段提供清楚输入。审核贯穿工作流，不等到最终交付才检查逻辑。

内容审阅单设负责人 Agent。该负责人组织正式排版前的整案审读，汇总事实、逻辑、重复内容、措辞与图文一致性问题，交由对应板块负责人修改，并复核受影响内容。比稿 Agent 检查处理结果与整案衔接。独立裁判继续按各阶段约定工作，创作者不能自签独立通过。

| 视觉开发 | 视觉负责人按[统一 Skill](../../skills/visual-development-lead/SKILL.md)执行参考、草图、精修及相应评审 | 沿用已确认的方向切换、参考、草图、成稿与样机布局，按任务适配；准入、授权、版本与轮次按 Skill 核对 |

| 终审与交付 | 比稿 Agent 组织独立终审及交付核对 | 审核排版后的实际呈现、内容完整性与产物；按实际通过范围交付 |

策略使用最新简化要求，不恢复旧强制策略 Skill、固定评分表或多轮角色评审。研究仍以适用证据回答任务问题，关键依据不足则保留“研究待补”。经授权讨论的下游草案保留条件和原生成身份，不能倒写上游通过。

### 阶段交接与页面审核

每次交接带上任务版本、有效上游产物、证据或素材引用、用户约束、待补项、已发生的评审与修改，以及下一阶段要解决的问题。发现来源、事实或逻辑问题时退回对应负责人，修改后核验受影响范围。上游改变后，重新检查依赖它的结论和页面。

每轮页面完成或修改后使用 `ui-review` 检查实际界面并优化。检查信息是否直观、是否冗余重复、操作是否清楚，以及与前后板块的配色、字体层级、间距、卡片、图表和侧栏是否协调。沿用用户已认可的桌面端、中文界面及版式体系，按阅读任务选模板；复用不要求所有板块采用相同布局。

内容评审、跨阶段审核和 UI 审核各自保留结论。UI 审核通过不改变业务阶段状态。实际界面无法核验时写明未验，不以构建或文档检查代替。

内容审阅在正式排版前完成整案内容检查。排版后终审另行检查实际渲染和交付，两轮分别记录。自动或辅助模式及人工节点继续按[三级协作约定](任务范围与三级协作.md)执行，暂停和授权边界以具体项目最新决定为准。

#### 状态顺序与交接

1. **任务卡**：核心问题、产品阶段、交付物、节点、年龄、购买/使用角色、资料窗口、竞品参照和边界。用户确认后正式搜集。
2. **多线搜集**：品牌资产及阶段主张、同类案例及变化、用户/场景专业资料按任务并行。来源、SKU、时期、原图身份与缺口随结论交接；不只交摘要。
3. **策略正文**：品牌资产取舍 → 为什么比较竞品 → 品类共性/品牌区别 → 购买场景 → 三圈交集 → 回答核心问题。以品牌策略立场撰写；每段有决策含义，段间有问题承接。
4. **策略审校**：先润色，再由未参与撰写的品牌负责人视角复核。此阶段不加入用户裁判。分析框架必须产出具体选择，术语不替代证据。
5. **主题创作**：文案总监基于三圈交集形成稳健延续、产品特征放大、用户氛围或情绪放大三个实质不同方向。先写可直白复述的主张，再写主题与副文，最后设计画面。
6. **主题评审**：文案、品牌、用户、传播独立评审。输入不含作者推荐、旧分数与其他裁判意见。既审单案，也审三案横向差异；用主副文互换测试区分主张差异与执行变化。先内部修改通过，再给用户看，避免反复提交未成熟候选。
7. **美术定向与参考**：从已成立创意找匹配图，可跨行业。将构图/风格/光线/空间比例/产品融入写成可观察标准。艺术参考与用户偏好证据分开。参考由视觉总监内部选定，独立评审后冻结；用户取消逐张参考确认不等于取消参考评审。当前生产生图按用户要求暂停。
8. **视觉制作与评审**：按《结构与美术分阶段评审.md》执行：用途与核心创意 → 结构草图评审 → 美术表达评审 → 整体复核。结构未通过不精修，结构通过不代表终稿通过。视觉总监定向，设计执行，独立视觉/品牌/用户/传播裁判审实际稿，文案裁判检查图文，沿用适用的对抗审查。达标可提前结束，否则按常规最多三次修改，再按约定专项优化；每版和意见留存。此为业务流程，当前不恢复生图。
9. **整稿审校与提案排版**：文案负责人先统一全稿措辞与衔接，独立品牌策略审校通过后冻结内容版本。再沿用户认可的横向样章，一页一个主角。选页型而非换皮，信息多则拆页。排版与KV分别验收；需改文时退回文案并重验受影响页。当前梦之蓝可沿已认可v3版式展开，不重复确认。
10. **最终交付**：全稿品牌策略润色、来源及引用检查、实际运行截图及独立视觉验收。网页正文只放选用稿，来源、旧稿、过程评审收进独立入口。

#### 不允许替代的验收

- 模拟评审不代表真实消费者数据或品牌客户批准。
- 内容/文案pass不代表图像或页面美感pass；构建通过不代表实际渲染通过。
- 需要读图的裁判必须看实际图；只读文字时结果限定文字概念层。
- 当工具、审批或额度失败时记录未执行，不补造通过记录。
- 存在独立具体阻断项时不可用平均分抵消，也不能为“凑三案”放宽标准。
- 创作者与独立裁判分离。受污染的盲评输入须标记，必要时重新隔离评审。

#### 版本与模型替换

任务、证据、推导、创意、参考、图像、页面与评审均有ID、版本和父级关系。最新状态单独指向有效版本；历史失败记录显式标为历史，不覆盖原文。每个角色记录所需能力与实际执行模型，替换模型不得改变证据、确认节点和验收规则。尚未暴露真实模型/费用时如实记未知。
