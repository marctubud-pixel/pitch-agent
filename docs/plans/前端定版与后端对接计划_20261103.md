# 前端定版与后端对接计划

2026年11月3日。当前前端可以定为展示与本地交互基线。后续接入沿用现有视觉、八阶段、五个工作区和已通过的交互，优先复用后端已有实现，按“先读成果、再接动作、再接编辑交付”的顺序逐项验收。

本轮只形成定版记录与对接计划，不合并应用代码、不改接口、不启动联调服务，不操作当前后端案例、数据库、任务或预算。后续真实接入按各模块交付的稳定版本安排，不向当前开发节点插入新任务。

## 1. 定版范围

定版包为 `proposal-workbench-f05ab-f06a.zip`，已验收 F01–F04、F05 展示、F06 手机助手、F07 概览及后续三处补修的已测路径。包内297个文件已重新与 ZIP 核对一致。包身份、逐文件哈希及源目录见[定版基线记录](../../.scratch/frontend-backend-handoff-plan-20261103/baseline.json)，结论范围见[最新验收报告](../../output/reviews/frontend-f05ab-f06a-20261103/三处补修验收报告.md)。不重复复制大型包或迁移原件。

定版锁定以下用户体验：

- 字体、配色、卡片、按钮、布局风格及明暗主题。
- 八阶段和五个工作区的导航、阅读顺序与主要操作。
- 草稿归属和提交保护、证据定位返回、待审对象说明、作品大图。
- 中性的修改归属和同文定位、版本对照、助手隐藏恢复及概览快捷入口。
- 自动与辅助模式、已有人工检查点、来源和独立评审语义。

服务适配、数据转换、真实图片渲染和命令接线可以按下列计划修改。必要的支撑改动要保留上述体验，并通过回归；新增业务决定、强制确认节点、账号计费或视觉重设计不随本计划实施。

该包尚未合入正式 `apps/proposal-workbench`。历史展示验收不等于已完成真实接口、真实模型质量、实际手机软键盘或全产品验收。

## 2. 先区分三个入口

| 入口 | 当前核查事实 | 对接时的处理 |
|---|---|---|
| 已验收定版包 | HTTP 适配仍有占位；即使设置 API 地址，创作阶段仍使用 MockProposalService。真实图片也还不能仅靠给程序画作一个 URL 完成接入。 | 作为视觉与交互参照，不把开关切到 HTTP 就宣布已连接。 |
| 当前正式 React 工程 | 已有部分项目、任务卡、研究和模式 HTTP 适配；创作投影主要为摘要，正文及多类写动作尚未接通。 | 复用已实现的 DTO、映射、错误处理和订阅；逐项迁入独立集成副本，不整目录覆盖任何一方。 |
| 后端及独立工程验收页 | 已有阶段执行、版本、人工节点、参考输入、编辑保存/恢复和指定版导出能力，各自有适用范围。 | 复用业务实现和接口语义，将结果接入定版界面；工程页不作为正式 UI，组件测试不相加成全链路通过。 |

普通 `/api/v1` 项目接口，与独立本地验收的 `/api/cases`、文档接口属于不同合同。独立入口的测试会话、数据根、配置身份及权限不能直接混入普通 API。具体选择在接线前按后端交付版本确定，不为本次计划重配现有入口。

事实落点见[前端接缝核查](../../.scratch/frontend-backend-handoff-plan-20261103/frontend-inventory.md)、[后端能力核查](../../.scratch/frontend-backend-handoff-plan-20261103/backend-inventory.md)、[正式服务装配](../../apps/proposal-workbench/src/services/index.ts)及[普通 API 合同](../versioned-api-v1.md)。

## 3. 推荐推进顺序

| 顺序 | 要完成的工作 | 完成这一批的验收条件 |
|---|---|---|
| 0，现在 | 固定展示基线，建立页面、数据和命令对照表的框架，后续逐项补齐，划清演示、已接与未接能力。 | 包和验收记录可定位；三类入口差异明确；不替换正式应用，不操作后端。 |
| 1，接线前 | 对齐后端入口版本、能力、字段、资源及错误合同。收集隔离样例，列出哪些能力可复用、缺适配或尚未提供。 | 每个页面的数据来源、项目/产物/版本身份、缺失状态和允许动作有对应依据；没有拿演示字段强迫后端改业务。 |
| 2，先接只读 | 从项目与任务卡开始，接研究证据，再逐阶段接策略、文案、参考/草图/视觉、内容、排版和终审成果；同步接真实媒体、历史和任务状态。 | 五区关联同一项目及各自明确对应的当前/历史版本；能读稿件、证据限制和阻断原因；真实接入路径不混入定时生成的演示正文。缺结果明确说明，不用示例补齐。 |
| 3，再接写动作 | 先复用创建、任务卡保存确认和模式配置；再接后端允许的研究核验/续接、已配置人工节点的决定、阶段意见及合法定向修订。 | 每个动作独立验证写入、刷新、重开、重复提交、版本冲突和丢响应对账；决定绑定用户实际看到的稿件，意见记录与启动改稿分开。 |
| 4，再接编辑交付 | 将后端实际排版和终审成果接入现有交付区；复用后端统一编辑文档、保存历史、追加恢复、指定保存版本 PPTX 和下载。 | 实际案例可编辑、保存、重开和恢复；预览、保存版及下载回执对应同一文档版本；文件对象和资源可核对；工作稿身份保留。 |
| 5，完成整体验收 | 用 KV 与包装案例覆盖自动及辅助模式，完成输入到最终文件的浏览器操作、重开恢复和视觉回归。 | 阶段成果、人工决定、修改记录、版本、原件及最终文件能逐项对应；失败与未知不会触发重复派发；F01–F07 已通过体验保留。 |
| 6，后置增强 | 在项目投影可靠后接 WorkBot 的实际记录问答，再评估增量成果展示等体验。 | 回答引用当前项目和版本，入口可定位；没有能力时如实说明；助手不替用户批准、改稿或放行。 |

这不是要求等所有读接口完成后才做任何写动作。第2、3步按模块形成小闭环：该模块先能正确显示实际成果与依据，再开放其写入动作；每个单元通过后再继续。各模块也不必等整个后端项目结束，只需拿到明确、稳定且可隔离验证的交付。

WorkBot 的定位、隐藏和恢复属于已定版体验，继续保留；实际问答服务单列，优先保证业务主链和交付。定版包附带的“先助手后创作”顺序是通用参考，本项目按当前已有能力采用以上顺序。

## 4. 八阶段分别接什么

| 界面阶段 | 优先接入的数据和动作 | 需要保留的含义 |
|---|---|---|
| 简报与任务 | 原始输入与附件、字段出处、任务卡版本、未知项、保存与明确确认。 | 本地文字提取/标题匹配不冒充模型理解；旧任务卡确认不自动适用新稿。 |
| 研究 | 研究正文、论点、来源摘录、日期/范围、核验限制、就绪与交接状态。 | 缺来源与未核验清楚可见；模型负责人交接不由人工按钮冒充。 |
| 策略 | 三圈、交集、问题、推荐切口、推导与证据引用；合法意见和修订。 | 展示可读依据和缺口，不要求展示全部内部思考；文本相同不证明采用。 |
| 文案与主题 | 三方向、标题/副文案/创意说明、评审、用户意见、采用和修订关系。 | 用户保留、已采用、独立评审通过分别显示；按任务允许范围修改。 |
| 视觉开发 | 参考池、用途和采纳、候选/草图/精修、实际图片、方向作品版本及评审。 | 后端参考、草图、视觉细分步骤映射进现有阶段；材料已登记不等于已采用，不新增主阶段。 |
| 内容审阅 | 完整文稿、修改段落、原文与原因、检查结果、未解决项及可排版版本。 | 人工编辑使用中性归属；缺少检查到段落的关联就明确未记录。 |
| 版式 | 实际页面、风格资格、字体/图片/图表资源、布局版本和终审状态。 | 不用演示固定幻灯片替代实际内容；不因用户编辑而自动获得复核通过。 |
| 终审与交付 | 终审结果、当前交付稿、编辑文档、保存历史、恢复、确切版本导出和下载。 | 后端交付资格为准；翻页不等于批准，下载成功不等于业务终审通过。 |

前端八阶段与后端细分工作流保持映射关系。五个工作区仍为概览、提案、资料库、流程与历史、交付，WorkBot 保持现有旁侧入口。

## 5. 接口对照表需要包含的内容

实施前按每个页面和动作逐项填表，不要求后端新造一个包含全部内容的大接口。

| 类别 | 要对齐的信息 |
|---|---|
| 项目与来源 | 项目/案例身份、任务卡、后端入口及配置版本，持久化成果或演示数据的来源。实际本地合成成果与真实模型成果分别标明。 |
| 版本与关系 | 项目 revision、阶段/作品/评审目标及父链、当前或过期状态、编辑文档 revision。各版本域分别绑定，不能用产物数量猜版本，也不能共用一个“v2”替代所有含义。 |
| 任务与能力 | 可执行动作、等待用户/处理中/阻断/失败/结果未知及原因，前置条件、计划任务与实际成果、部分完成状态。费用缺数据则显示未知，不变成0，不在此引入计费系统。 |
| 媒体与文件 | 资源ID、项目与方向/版本归属、受管理预览/下载入口、类型、尺寸/比例、来源和完整性信息，加载失败与原件缺失提示。不能把磁盘路径当浏览器URL。 |
| 意见与修改 | 意见ID、归属阶段/方向/作品、原文、处理状态、回应及真实修订/采用关联。无关联保持中性，不按文本相等或时间先后伪造因果。 |
| 写入与回执 | 该接口实际要求的命令身份、版本前提和输入摘要，成功回执、冲突、明确拒绝、未知结果及查询方法。普通项目命令与工程编辑请求分别核对，不能机械套用附件占位请求头。 |
| 导出 | 文档ID、明确保存版本、文档哈希、格式、导出状态、下载回执及文件身份，原件与版本失效时的行为。 |

前端真实 JSON 在适配边界校验后进入展示模型。缺字段、未接入、未记录和明确没有变化分别表达，不能统一填空数组后显示“没有问题”。

## 6. 写动作与交付的重点

写动作以真实回执更新界面。双击保护只是第一层，还需沿用后端的命令身份和版本检查。断网、5xx 或响应丢失时，先读取回执或当前状态；同一已知意图按相应合同处理，不能换新ID直接再次派发。明确拒绝、需要修正输入、结果未知分别处理。

确认继续必须绑定实际已查看的成果与有效依据。普通页面上的 `decide` 不能被直接翻译成一个绕过负责人交接或事实核验的通用批准接口。自动模式在既有授权、预算和门禁内继续，辅助模式只在已配置节点等待用户，不新增逐阶段强制确认。

在线编辑复用现有文档存储和版本机制。保存、历史、追加恢复与导出分别验证；恢复不覆盖历史。编辑后的文稿和图表保留工作稿/待复核身份，不能继承原稿的全部事实或终审批准。

指定版导出绑定确切保存版本及实际资源。现有前端浏览器 PPTX 生成与后端统一编辑文档的导出不是同一条链，不能因为示例下载成功就声称指定版交付已通。当前工程编辑桥仅支持 editorial 文档，三套排版回执不等于三风格在线编辑均支持；未支持的风格明确说明，不自动补齐。导出也尚不具备保存/恢复同等的命令回执协议，未知导出不自动重导。相关实现见[编辑版本存储](../../tools/auto-layout/editable-proposal.mjs)、[工程编辑桥](../../tools/workbench/local-engineering-editor-bridge.mjs)。

## 7. 现在准备与后续开工条件

**本轮已完成：** 定版包和源文件身份复核、两个前端入口与已有后端能力的只读盘点、对接清单框架和验收顺序。逐动作的URL、请求、响应和字段映射仍需在接线前逐项补齐。没有开始适配实现，也没有验证实时服务或任务状态。

**现在可安排的独立准备：** 细化字段/动作矩阵，整理已保存且可引用的响应样例，记录真实/合成/演示来源，准备视觉基线与异常场景清单。后续离线适配代码和测试可放独立副本开展，但本轮不执行这些实现。

**实际联调前，由当前节点交付方提供：**

1. 可消费的源码/API/运行配置身份、当前支持能力与已知限制。
2. 可用的隔离入口和数据根，保证不会写当前案例或改变现有任务。
3. 每个待接动作的版本前提、权限/门禁、回执与未知结果处理方法。
4. 对应模块的验收回执和实际成果样例，候选与已集成能力分开列明。

完整案例的编辑与最终导出验收，还要等待对应业务产物确实完成、来源及门禁有效，原写入者已经结束并有可操作窗口，再逐案进行。开发状态按[状态导航](../../status/current.md)、[开发说明当前段](../../多线调研工作台_开发说明_v0.3.md)和[CHECKPOINT](../../.scratch/end-to-end-local-20261102/CHECKPOINT.md)的最新原生记录核对，不按历史 running 文案重启或迁移任务。

## 8. 每批交付记录

每批至少保存页面与动作范围、前后端身份、使用的隔离项目、当前/历史版本、请求与回执、实际浏览器操作和视觉对照、已执行的检查及未覆盖内容。按可验收单元推进，通过后再进入下一批，避免最后一次性集成才发现项目、版本或来源不一致。

最终验收包括自动与辅助模式、局部修改及关联失效、刷新与重开、重复操作、版本冲突、响应丢失、原件缺失、历史恢复、实际媒体、手机阅读与输入，以及指定保存版 PPTX 的原生文字/图片/图表及文件身份检查。此前的展示验收与后端工程检查各自保留，不替代新基线的浏览器闭环。

本计划经[独立综合复核](../../.scratch/frontend-backend-handoff-plan-20261103/final-review.md)，已收紧对照表完成程度和各版本域的表述。复核独立重算定版 ZIP 及297个文件，均与基线记录一致；它没有执行真实联调或完整会话逐条审计。
