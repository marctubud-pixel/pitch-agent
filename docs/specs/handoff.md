# 版本与阶段交接

规范版本：1.1.0。用于开发和人工编排交接，保留现有后端DTO、数据库和回执合同，不新增业务API。

## 执行前

读取本任务适用的规范注册项和锁，不将“最新聊天摘要”当成唯一方法。核对当前Brief、上游稿件、实际素材、授权终点、人工节点和已知限制；版本失配先对账，未知写入结果只读核账。项目当前状态从原生回执定位，长期岗位文档不缓存某个案例“现在可以画图”等临时授权。

## 最小交接记录

| 内容 | 应记录的实际值 |
| --- | --- |
| 对象 | 项目、任务、阶段、当前Brief／head及本次授权范围 |
| 双方 | 派出岗位与实际执行者、接收岗位与实际执行者；独立评审者另记 |
| 规范 | 适用岗位ID、页面ID、各自版本；实际Skill／模板源版本及SHA |
| 输入 | 有效上游产物版本、原图／证据引用及哈希；未提供就标未知 |
| 结果 | 本次实际文件、版本、路径、SHA和内容性质：原件／设定／生成示意／演练／正式 |
| 核验 | 实际执行的独立评审、UI检查、命令和原生回执；未执行说明未验 |
| 未决 | 新问题、已知随稿限制、下一负责人及应复核范围 |
| 接收 | 接受／退修／待核，实际接收人、时间、理由及需补对象；收到文件不等于接受 |

无需给用户再堆一份冗长报告；记录可简短，但必须可回到原件。没有暴露的模型ID为未知，不补成品牌或不同模型。

## 接单闭环

1. 上游负责人提交交接包和实际自查，保留当前身份及未决限制。
2. 下游负责人核本阶段所需输入、版本、材料和授权，明确接收结论。缺件列清补给谁，错版先对账。
3. 比稿Agent检查跨阶段承接；需要独立评审的阶段保留其原票和结论。策略沿用基础核验，不额外加评审门槛。
4. 接收后在授权范围内执行；退修改稿产生新身份，再核受影响范围。生产者自查不能代下游签收，待核不能写已接收。

可在既有任务记录中使用以下最小模板，无须另建重复台账。

```yaml
对象: 项目 / 阶段 / Brief与head / 授权终点
派出: 岗位 / 实际执行者
接收: 岗位 / 实际执行者
依据: 注册项及版本 / 实际方法版本
输入: 原件路径及版本与SHA / 已知限制
交出: 产物路径及版本与SHA / 自查及独立原评路径
接单结论: 接受或退修或待核 / 时间 / 原因
下一步: 责任人 / 需补对象 / 重核范围
```

## 分开记录审核结果

| 审核对象 | 承担者 | 完成证据 |
| --- | --- | --- |
| 内容与阶段方法 | 当前业务负责人及适用独立评审者 | 同版产物、原评、异议与裁定 |
| 阶段衔接 | 比稿Agent | 输入与输出关系、有效交接或退回 |
| 实现与规范 | 开发实现者及独立代码复核者 | 固定差异、验证、问题处置 |
| 页面UI | UI负责人组织，独立UI审核者复验 | 实际界面、交互、前后证据与未验状态 |
| 排版后终审 | 终审负责人组织，独立职责及裁定者执行 | [终审协议](final-review.md)要求的实际页与同版产物 |
| 人类决定与正式交付 | 有权限的人类比稿负责人及交付接收者 | 同版真实决定引用、最终对象与实际交付回执 |

每项分别写已执行、未执行或待核及实际结论，不能用一处“最终审核通过”代替所有结果。

## 修改与推进

每次改稿产生新身份，原稿、原票与原裁定保留。上游改变只重核受影响结论和页面，旧通过不能套到新版本。已知演练限制不反复生成相同待办；新增矛盾、错版和缺件按当前岗位退回。

内容完成、独立评审通过、UI通过、人类确认、导出成功和正式交付是不同结果。页面导航和等待超时不构成批准。创作者、评分者、对抗者与裁定者按适用阶段保持分离；策略的最新简化规则不因本通用合同恢复复杂评分流程。
