# 夜航提案台运行合同

规范版本：1.44.0。此合同适用于实际交付的 `tools/nightflight`、桌面 App 和个人站。个人站按单一所有者部署。

## 单一比稿负责人实验

此分支的新任务由同一位比稿负责人读简报、查研究、写策略、创作文案、组织视觉、调用排版和处理终审意见。七个页面表示工作步骤。项目数据库中的原件、用户选择、研究缺口及反馈构成负责人跨调用的记忆。各步骤按需加载研究、一页策略、slogan 和视觉的方法。旧岗位组织文档供比较，不作为此分支的派岗清单。

只有并行搜参考、同批候选生图及独立审查使用临时执行者。文案由 DeepSeek 使用原版 slogan-engine 起稿并每案自选一句。负责人从这三句推荐一案，历史文案按原记录阅读。视觉审查保留四岗证据，采用记录由人决定并随返修传递。排版继续用 Deck Studio。

| 页面 | 运行阶段 | 输入、交接与人工决定 |
| --- | --- | --- |
| 简报与任务 | brief | 保存任务卡。协作模式需确认后启动研究。 |
| 研究 | research | 已核发现优先显示。同版交接已核发现、证据和仍有的缺口。 |
| 策略 | strategy | 全部新策略使用夜航一页纸。独立读者只收首页文字，逐句指出表达障碍；由负责人处理措辞并记录。触点覆盖实际委托的包装面及 KV 场景，未指定媒介时按条件说明。 |
| 文案与主题 | copy | 从上游策略自拟三案。作者核对自选主标和三案差异，负责人从通过的三句推荐一案。切换方向显示该案副标和备选。协作模式可以反馈或选方向。 |
| 视觉开发 | visual | 同方向的三张稿共用一张主参考，采用[借三改二](../../skills/visual-development-lead/SKILL.md#借三改二)的三组组合。桌面调用配置的文字 API 写稿，最终提示词随实际图片发给生图 API。人可指定候选并记录与推荐不同的理由。修改次数按项目本轮计算。 |
| 版式 | layout | 采用时可选择只整理材料包或写逐页稿。两者均保留本版材料和原图观察。选择排版时，生成同批可编辑 PPTX、预览与逐页审阅图。 |
| 终审与交付 | final | 核对同版 PPTX 和实图，经三岗审读、合批直修与复验交待验收稿。提案人验收后完成。 |

历史规范使用 themes／delivery，合同后端使用 copy／final_review；分别对应上面的 copy／final。项目 ID、附件与历史记录随本应用数据库保存。自动模式按现有授权运行；运行中遇到需要重试或补材料时保留本轮可复用结果。运行中的反馈应明确告知是否接收。已完成项目的修改从受影响阶段开始。

桌面采用区的「采用并写逐页稿」从当前版取原 Brief、任务卡、研究发现和出处、策略正文、各案文案与采用原图。策略正文核对文案交接的文件指纹，采用图按实际选稿取字节。夜航的读图 API 先逐张记录图号、可见内容、原字与未核信息，再把观察与文字材料交给 DeepSeek。同版记录保存完整逐页稿、可直接使用的材料包、DeepSeek 实际请求及读图回执。阶段停在版式供查看，重试复用同一版本已完成的模型回执。

DeepSeek 编稿时加载 [ppt-slide-script v4](../../skills/ppt-slide-script/SKILL.md) 的正文、提案模板和措辞精简方法。目录只列 3–5 个章名。已有趋势和同类研究分别成页。核心策略独立成页，执行要点随后展开。按委托载体编排逐案阐述和采用图，单活动沿用混合模板的活动模块。夜航把同版主副标逐字写入各案阐述，以实际编号及文件名标出图位。多案展示完再比较，随后列明建议或待决定事项。轻量海报和多案 TVC 概念在材料未给全案推荐时请客户选择。内部审图和制作提醒留在内部备注。

版式页的「按逐页稿排版」读取同版页序、文案、依据和图位。排前核对上游版本、策略及原图指纹。夜航使用技能包里的 [Deck Studio 路径](../../skills/ppt-slide-script/references/deck-studio-bridge.md)，一页稿对应一页可编辑 PPTX。阐述页以文案和该案图片分屏，作品页保留整图。内部备注和来源原址进入演讲者备注。页脚取已确认品牌名，品牌待定时使用本版封面的短标题或「设计提案」。预览、PPTX 和逐页审读图使用同一批排版数据。视觉采用区在已配置模型时也可直接编稿并排版。历史项目保留原排版方式。

逐页稿排版走[Case B 本地终审](nightflight-final-reader.md)。进入前核版次、原生 PPTX 正文和图片、演讲者备注及逐页渲染。三岗独立请求使用已配置的视觉理解模型。直修意见按改法归到版式，再核本版原文、证据和权限。超出权限的终审意见须给出实际责任阶段，交提案人决定。直修以本版逐页数据为底稿，仍用 Deck Studio 导出原生 PPTX 和实图。新版保留原页序、已定策略、主副标和采用原图。全览和修改页完成复检，权限或 P0 问题留给提案人处理。只有用户验收该精修版后本地阶段才完成。旧版无逐页计划的稿件沿用本地审读记录。

终审复验逐批给当前岗本批实页、原件和该岗原有意见。略长但可读的文字、一般断行、留白是 P1。事实错写、已确认内容缺失或关键图文不可辨时，按实际证据记 P0。先保存有页码和证据的意见，有对应动作再直修。需重做采用图等上游问题保留给责任阶段。复验后对余下 P0 单独核对该页应有内容、本版实际图文及已确认原文。按问题类别保存实际抄到的字样、已确认的原句、位置及依据。核实为可读的优化建议、已看到所需原文或该现象实际不存在时，按 P1 留在回执。证据成立或仍未核清的 P0 继续阻断。

「采用并整理材料包」复用同版取材和原图读取。在版式保存供手工编稿的材料包和读图回执，等待用户查看。文字编稿和排版各有独立操作。

现行发布验收覆盖真实夜航服务、交互及存储；经典后端的回归单独记录。公开网络、真实模型调用及上线域名按实际测试环境另验。

视觉开发取同版研究已核的包装与传播原图，按来源页、原图和文件指纹加入候选。先按短图号选 A、B、C 各方向的唯一主参考，再补辅助。品牌案例目录每页先取一张原图，再补同页其他图。各方向仍须按创意选择不同的专用主参考、核对用途并通过既定独立准入。公开参考先逐图登记实际可见内容。准入记录按图号区分参考原件的实见特征和本案拟转译的做法，成图后再核印字、规格与实际相似度。参考四岗各自记录 1 至 5 分和有证问题，独立裁定逐岗写明通过或阻断，可另指出看图或拟借法时发现的具体新问题。首轮借法未过，作者先对照准入意见重配借法，再按现行门槛核对。缺主参考时先按通用品类打开品牌发布案例。已有新图而个别方向仍缺时，按本方向缺的画法、动作或场景改用短词搜，也可搜能说明同种画面关系的相邻品类。每个缺图方向最多补查两轮。

已完成独立准入的方向保存原图、拟借用法以及原票。其他方向补查或重配借法时，只提交这些待处理的方向。已准入的专用参考图保有原归属，作为其余方向的对照。

桌面先按本版策略和文案提炼每案的美术任务，记录请求身份。选图、补查及准入使用画面关系、拟转译方式与实见原图，优先查相近载体。相邻题材能承接同种布局、表现、动作或氛围时可参与比较。制图和成稿核验读取本轮的商品规格、品牌及文案原字。

桌面每张主视觉的回执记录文字模型、文字请求编号、实际提示词、生图请求身份、借改项目和实际附图。文字响应缺少可用的制图内容时，该张出图须等待文字重试。同批候选的独立盲读和四岗评审可并行请求，独立裁定等原票及对抗齐全。评分、对抗与裁定各为前三张候选提交三个固定位置的意见，只在候选理由中引用后续参照。包装任务把主题交给提示词作者做画面转译，包装印字按已确认的产品资料交接。成稿的同类包装对照直接使用同版研究已核的真实包装及指纹。已有对照按实际形态和适用范围比较，缺少已核原件时重新找样。品牌岗逐稿核盒身字样和位置，主题或其他不符用途的文字印在本体、字样错误或印字无法核实时，自动推荐排除该稿。隔离演练可用 `NIGHTFLIGHT_IMAGE_MODEL` 为当前生图进程指定模型，保存的设置仍由用户在桌面菜单维护。

桌面并排评分、对抗和裁定可以使用较大的原图所生成的轻量阅览版，保存原件和阅览版的指纹。品牌原票指出印字有问题或无法读清时，独立读者只收该张原图和产品 Brief，逐字抄录包装本体和实际位置。核验结果与原票分别保留，裁定依据原图核验处理印字问题。原图确有错印或无法核清时仍退出自动推荐。

明确委托的海报／KV 逐方向沿用本版定稿 slogan。画面也包含包装时，海报标题和盒身印字分别按对应位置核对。提示词可以用连续的行写全主标题，标注「第一行、第二行」时须按顺序列全。夜航发送前核对原字、数字、标点和英文词间分隔，将实际提示词原样交给生图 API。核对图上标题时，独立读图逐张读候选原图，保存抄录的字和位置。程序允许换行和中文排版留空，保留英文词间分隔，逐字核对原句。漏写、改字或看不清的图稿退出自动推荐，并在评审详情留下原因。全自动的方向没有达标稿时，只有标题标点不同、评审均分已达 4 且其他检查通过的稿子可局部修一次。保留初稿与原票，替换这一张并重新独立评审该方向；仍无达标稿时停在视觉开发。

桌面单独委托海报／KV 时，夜航给提示词作者传递策略目的、当前创意和客户明确约束。原图读图回执锁定三项要借的特征，文字 API 交回两项改法以及主体、背景和画面文字。程序把这些内容与定稿原句组装后，随实际主参考送入生图 API。出图后每案的三张与主参考同场核对五项。全自动的三案再用实际代表稿比较三对构图。主要布局、景别和焦点关系雷同时，换画风也须退回。借改未核或构图雷同时保留稿件及原票，相关稿件退出自动推荐。

桌面「视觉理解」在首次配置时预填 OpenAI 的 `gpt-6.2-sol`。已有配置按菜单保存的服务和模型执行。带图的读图与评审回执记录实际返回的模型。

研究使用一份四维计划：行业与市场、竞品、用户、产品与品牌。包装竞品保存可辨认原图、实际观察、来源页和原图地址。负责人核对原件后直接写行业、竞品、用户、产品与品牌四块。每条先说结论再给依据及出处，产品与品牌比较卖点主次。研究无单独复核或摘要编辑，补查沿用证据并更新缺口。桌面研究的模型回复无法解析为 JSON 时，沿用当前材料只重问该项一次，原有证据校验继续执行。确认任务卡时可指定仅运行研究。

找竞品图时先按通用品类分别找包装和海报，再查品牌、具体商品或活动。优先用计划中能代表同类的简单类别词，报告封面及图表不得算作已发布的传播海报。包装优先走品牌品类目录、形态栏目和商品页，按图上实际商品核对品类。海报从发布作品正文取原图，每张图随自己的正文单独读图并登记原图编号，电商活动作品记录实际渠道。包装正面、详情页首屏只约束涉及该位置的结论。同一品牌的包装搜索与海报搜索分别保留。首选品牌无合格包装时，从本轮打开的同类作品发现备用商品品牌。只有品牌已在案例核实且官网仍缺，才单独用公开品牌名补找官网线索。实际打开并核对站点身份，再按商品目录找图。品牌查找并行，保留原有结果顺序。包装读图接收检查项目和原图局部，规格、数量和配料按原图实见写。

海报的发出、投放和活动开展证据随其发布正文保留。读图可以按本图来源原句的编号选择证据。夜航取原文，并核对所属页面、原图、物料和实际发布记录。

研究可通过 NIGHTFLIGHT_SEARCH_RSS_URL 配置检索，日志记录查询结果数。公开词返回偏题或不可用时切换机构目录。行业用词包括通用短称，独立查询可以并行查找。题名为上位品类的报告按实读正文决定是否采用，按原品类和年份标注实际数据与预测。行业、竞品、用户的两三条结论是呈现目标；交接核对实际研究能否支持策略。

版式先按项目载体和逐页稿匹配 Deck Studio 模板，再用实际材料校准。市场图数值与统计口径同源。预览和 PPTX 使用同版颜色、已提供的品牌标志和人工选稿。缺少可用素材或版式超限时记录回退与分页。

研究交付已核结论、出处、策略用途及未知条件。全自动模式进入策略前，行业、竞品、用户、产品与品牌各需有据结论，用户画像有两条独立且有出处的信息即达标。同一道题的多个选项合计一条，其他用户题目仅因未覆盖不阻断交接。以上证据条件通过时进入策略，未证实的具体规格、细分和价格条件作为有边界的缺口传递。海报委托须有同类品牌实际发布的海报原图及发布记录。关键资料未齐时换词、换来源补查；仍缺就停在研究，列出具体缺项。明确只运行研究时停在研究检查点。通用、包装和 KV 策略直接写稿，稿内标明适用范围和假设。策略阶段没有自动退回研究的动作。

## 单负责人分支的简报验收

生成任务卡前，比稿负责人先核对客户明确委托的成果。范围为包装、海报／KV、TVC、活动四类，支持单项和任意组合。范围未明或超出时，通过项目消息请求澄清，停在简报阶段，不生成任务卡、不启动研究。对客户补充的委托重新判断，通过后再按当前模式处理任务卡与研究交接。

按原话收齐已给的任务、人群、价格与渠道。“产品卖点与亮点”并列客户提供的产品特点。“客户当前判断”仅在客户表达主次、独特性或偏好时呈现。“硬性设计要求”仅在原话明确要求执行时呈现，保留限定词与否定。各项原话存入底稿。市场差异及优先发力点交由研究与策略判断；涉及改变硬性要求时由客户决定。每个未知项说明对下一步研究的影响和暂行做法。
