# 夜航提案台运行合同

规范版本：1.0.0。此合同适用于实际交付的 `tools/nightflight`、桌面 App 和个人站。个人站按单一所有者部署。

| 页面 | 运行阶段 | 输入、交接与人工决定 |
| --- | --- | --- |
| 简报与任务 | brief | 保存任务卡。协作模式需确认后启动研究。 |
| 研究 | research | 已核发现优先显示。按证据逐条记录缺口，依据能支撑发力点才交接策略。 |
| 策略 | strategy | 包装与 KV 使用直接推导的一页纸，其他载体保留原三板块方法。 |
| 文案与主题 | copy | 上游策略约束三案，保留候选、修改与双团复核。协作模式可以反馈或选方向。 |
| 视觉开发 | visual | AI 推荐保留原票，人可指定候选并记录与推荐不同的理由。修改次数按项目本轮计算。 |
| 版式 | layout | 生成同批可编辑 PPTX、预览与逐页审阅图。 |
| 终审与交付 | final | 读取排版产物及实图，记录通过或指定阶段和退回原因。模型判断不代签客户批准。 |

历史规范使用 themes／delivery，合同后端使用 copy／final_review；分别对应上面的 copy／final。项目 ID、附件与历史记录随本应用数据库保存。自动模式按现有授权运行；运行中遇到需要重试或补材料时保留本轮可复用结果。运行中的反馈应明确告知是否接收。已完成项目的修改从受影响阶段开始。

现行发布验收覆盖真实夜航服务、交互及存储；经典后端的回归单独记录。公开网络、真实模型调用及上线域名按实际测试环境另验。

研究可通过 NIGHTFLIGHT_SEARCH_RSS_URL 配置检索，日志记录查询结果数。行业、竞品、用户的两三条结论是呈现目标；交接核对实际研究能否支持策略。
