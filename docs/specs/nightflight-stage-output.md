# 夜航七阶段产出展示规范

规范版本：1.0.0。适用于夜航四栏工作区及其阶段详情。工作台 UI 负责人维护展示，阶段负责人提供内容，UI 审核者对照运行页面验收。

## 依据与适用范围

用户选定的「提案台-夜巡」独立 HTML 是视觉对照原件。其 SHA-256 为 `3c45cdcf3f3f9d9701fd7311e090d6e138925ba4544e5719d2877d90bc7b1a3e`，与源码 ZIP 内 `proposal-workbench/standalone/proposal-workbench.html` 一致。重查原版时从 ZIP 的 `src/components/Workspace.tsx`、`DetailSheet.tsx` 和 `src/styles/detail.css` 定位栏目、层次和间距。来源身份见仓库内的 `docs/development/source-import.json`。

栏目层级、顺序、主次和交互采用下表。文案、图片、页数、选择及检查结果均从当前项目相应版本取得。原型中的茶饮案例、示例访谈、模拟图、12 页和通过标记仅供原型演示。业务内容、交接和可执行操作仍按[页面责任索引](../pages/README.md)指向的阶段协议。新产物和旧项目共用这一套阅读顺序。

## 工作区与详情外壳

保留四栏。从左至右依次为主理人／接下来／项目、任务及修订、提案阶段、文档／视觉／提案预览／过往资料。主理人展示实际状态；证据不足和用户待选分别显示原因。文档与产物入口使用业务名称，点开定位所属阶段或对应产物。详情保留回到工作区、七阶段切换、阶段序号与状态、阶段标题。正文从业务栏目开始。文件名、原件下载、执行记录保存在二级信息或文末，技术标识不占用业务标题。

正文复用夜巡的 `.sheet-doc`（桌面最大宽度 1000 px）、`.sheet-head`、`.block` 和原有字号、细线与分组间距。任务卡 `.kv` 是标签列与内容列；`.findings` 左列编号；`.statement` 用大字提炼句；`.two-col` 按最小 300 px 分栏；`.dir-grid` 按最小 240 px 排方向；`.ref-row` 排说明与参考图；`.kv-row` 排图稿与图注；`.deck-stage`、`.deck-ctrl`、`.deck-strip` 分别承载当前页、翻页与缩略页；`.review` 承载检查项。遇到长文或窄桌面，沿原型断点换行，阅读顺序保持一致。

## 阶段栏目与数据绑定

| 阶段 | 原型阅读顺序与组件 | 当前项目如何填充 |
| --- | --- | --- |
| 简报与任务 | **你的原始需求**用引文；**项目任务卡**用键值表；已声明的假设紧接任务卡以列表显示。 | 引文取本案原始 Brief。任务卡从已保存稿中取客户／品牌、新品／品类、目标人群、上市时间、提案要求等实际字段。用户已定、待确认、研究假设保留各自身份。 |
| 研究 | **关键发现**用编号列表。每项先给判断与简短说明，再设可展开的**依据与来源**。 | 展示本版可核发现及对策略的用途，展开后给对应依据、来源名和已有链接。保留缺口、下一步、当前模式和补查交互；协作问题随有效发现和真实状态显示。历史研究稿缺少结构化核验记录时仍可阅读原稿。 |
| 策略 | **核心策略**先呈现提炼句，下面用双栏排有标题的论述。 | 从本次策略稿取得实际判断；研究结论、方向交叉点、策略发力点按现行合同映射。原型的人群洞察、品牌角色等是展示这种双栏结构的例子，无需为凑格子补写五项业务判断。 |
| 文案与主题 | **三个创意方向**横排方向卡。卡内顺序为方向编号和采用状态、名称、主文、创意说明、气质／场景／视觉／评估、示例文案。下接**主题文案**，用大字主张、说明和场景文案键值行。 | 方向、文案和描述分别绑定实际稿件的对应部分。选择动作和已选标记绑定当前协作选择；全自动三方向可同时存在。主题与场景文案仅展示能对应到指定方向的稿件。 |
| 视觉开发 | **视觉参考**按方向横排，左侧为方向说明，右侧为参考缩略图；再呈现**草图与主视觉**，以带图注的图组排草图、主视觉、已有延展。 | 只显示本案可定位的真实图片，按既有用途与方向分组；无法确认方向的项目参考资料明确标明其身份。生成概念稿、草图、参考和延展分别标注。图稿采用仍绑定用户审看的版本。 |
| 版式 | **提案预览**为主区域，先大页，再前后页、页码和缩略页带。 | 读取本次排版导出的同一 Deck，页数以实际文件为准。预览与可编辑 PPTX 对应同一版次；等待排版或缺少预览数据时展示对应状态，已有 PPTX 提供真实下载。 |
| 终审与交付 | **终稿提案**先展示可用 Deck 及交付动作；**终审记录**以状态标识、检查项和说明逐项展开；**你的反馈**收集并显示修改意见。 | 预览、PPTX、终审原件及反馈分别取同版实际记录。正式签收、本地审读和未核项目区分展示；没有结论的检查项保持待核。可操作按钮绑定实际下载与反馈提交，分享能力按接入状态呈现。 |

## 缺项与历史稿

- 区分阶段未开始、运行中、尚缺证据、待人选择、已产出。整块没有产物时说明阶段条件；某个字段缺失时隐藏该行或说明缺件。研究资料和创意素材允许部分到达。
- Markdown 原稿只能从已识别的标题、字段和段落提取内容。未知格式保留可阅读的正文和可下载的原件；展示组件不能补写洞察、重算评分或替用户批准。零份来源、没有图、未排版、无正式签收各自按记录显示。
- 界面切换栏目、展开来源和翻页均为阅读操作。生成、重查、选方向、采用、反馈按已有动作和版本校验执行。

## 专项验收

一个阶段产出展示改动用对应 UI 功能 PR 同步源码和规范。对照同一状态和桌面视口的 HTML 与实际页面，记录栏目顺序、首屏标题、卡片／双栏／图组位置、空态，以及原件和操作的去向。七阶段共用外壳变动时覆盖七个详情，另查桌面窄边界。使用可识别的隔离材料验证互动，真实项目只读核对。UI 验收不替代内容评审、终审签收或整链业务运行。

仓库根目录先执行 `npm run build`，再执行 `node apps/workbench-preview/scripts/check-nightflight-outputs.cjs`。指令只用于本规范对应的页面展示回归。
