# 文案三方向创作与交付

规范版本：1.1.0。适用夜航新项目的文案与主题阶段。创作者使用本方法构思三案，文案负责人按本版稿件组织独立评审。

## 构思与交稿

读取本版简报、研究与策略，再分别尝试三种创作任务，每种使用一次。方向名称按项目自拟，呈现顺序按本案安排。

| 创作任务 | 起点与写法 |
| --- | --- |
| 稳健延续 | 有品牌历史时，找出可以延续的语气、意象或成熟表达，并说明这次如何发展它。没有品牌历史时，可沿用本案研究有依据的品类常用表达，同时交代品类依据。 |
| 品牌或产品特征放大 | 选取有依据的一项品牌特征、配方、原料、工艺或使用特征，把它转成读者能想象的动作、比喻或画面。副文说清这个联想与产品事实的关系。 |
| 用户氛围或情绪放大 | 从研究支持的一个具体时刻或情境起笔，写清谁在做什么、产品何时出现，以及这句话如何契合当时的情绪。 |

每案提交以下字段。创作者在这里交候选稿，总监依据实际原票、异议及必要的复核记录给出推荐。

| 记录 | 内容 |
| --- | --- |
| 标识、职责、名称（`id`、`duty`、`name`） | A、B、C 各有一个方向，每项创作职责也各出现一次。 |
| 依据（`basis`） | 从本案当前上游材料逐字摘取可定位的一段原文，支撑这项创作选择。 |
| 主张、机制、策略承接（`claim`、`mechanism`、`strategyLink`） | 分别说明要让人记住什么、通过什么具体创意表达、与策略如何相连。用主副文互换检验差异，两案交换仍完全说得通时重写机制。 |
| 主文、副文（`main`、`secondary`） | 主文给读者一句完整的表达，副文补齐理解所需的动作、事实或情境。 |
| 触点（`touchpoints`） | 给出至少一个实际用途及对应文案。每条有 `label` 和 `text`，同一用途的备选沿用同一标签。 |
| 风险（`risk`） | 具体指出谁可能误读哪一句，或创意在哪种条件下难以成立。 |

## 夜航原型的三种写法

以下名称、主文和顺序均来自用户指定的「提案台-夜巡」独立 HTML，同源码包 `src/data/content.ts` 的 `DIRECTIONS` 对照核实。它们用于解释手法，新项目以本案事实和策略另行创作。

| 原位置 | 方向名 | 原主文 | 手法 |
| --- | --- | --- | --- |
| A | 慢半拍 | 今天，慢半拍也没关系。 | 用山雾和留白把“暂停半拍”变成可见的符号，让品牌已有的安静气质延伸到日常片刻。 |
| B | 夜里见 | 下班了，夜里见。 | 认领晚上八点以后的时段，以便利店冰柜、末班地铁和亮灯的窗，建立茶作为夜间无酒精选项的情境。 |
| C | 岩上生花 | 老岩茶，开新花。 | 把白桃和桂花的风味转成“岩石上开出花”的形象，以拼贴和贴纸表现新喝法。 |

这里 B 从使用情境出发，C 从风味出发。A、B、C 是原型中的展示次序。历史青屿继续使用其原方向、原句、推荐和原评审记录。

## 每岗分别评方向和成文

每岗对每案写四项原分。每项注明可定位的文字依据和给分理由，关键未知保留待核。下面的维度来自仓库保留的原始[文字概念评审约定](../../apps/workbench-preview/test-fixtures/provenance/originals/022-REVIEW-PROTOCOL.md)。

| 岗位 | 方向两项 | 成文两项 |
| --- | --- | --- |
| 文案 | 主张成立、同组创意机制差异 | 中文表达与节奏、主副文协作 |
| 品牌 | 策略及产品关联、品牌语义联系 | 事实边界、品牌/产品归属清楚 |
| 用户模拟 | 与设定选择情景的关联、利益或情绪的具体可理解性 | 直接理解、语言可信与不费解 |
| 传播 | 同组三案辨识、核心记忆线索潜力 | 简洁复述、主文副文的信息分工 |

每个分数都要交代适用范围。**4 分**表示这项表达已够本阶段文字概念使用，须引用本案文字解释成立之处。**5 分**还须明确参照基准，指明哪一句、哪种机制或哪处信息分工在该维度具体优于基准。角色分项保留原值，准入按适用必评逐项检查。比较范围为本次同组三案。“有记忆线索”评的是文案潜力，市场独创性、实际记忆率、购买偏好或传播效果需要各自的外部证据。

整组差异另写 A/B、A/C、B/C 三组比较。每对都比较主张与创意机制、情绪或情感立场、品牌与产品的语义关系、预期视觉载体如何承接文案。写出支持判断的具体原句，说明相同点及差异是否足以支撑两个方向。尚未出图的画面关系注明为待视觉验证的假设。

## 新稿何时能交给视觉

1. **四岗先读，再评。** 冻结本版三案和任务依据。文案、品牌、目标用户模拟、传播四岗各自先匿名读主副文，只记录理解、记忆点和不确定之处。第一包不含作者、方向名称、职责、创意解释、推荐或他岗意见。保存首读后，再提供任务、产品、品牌和研究依据，各岗结合自己的首读逐案逐维打分，并引用原文说明理由。
2. **四个对应对抗岗先找漏，再核票。** 每个对抗岗先独立读取稿件与任务依据，保存自己发现的遗漏、反证或实际空记录。之后才能看到对应岗位的原票，逐条指出原票已覆盖什么、哪些结论需要质疑、引文依据和可能后果。对抗岗不打分。
3. **总监逐条裁定。** 每项异议按原双团契约归入四类：本轮采纳（`accepted_now`）、延后采纳（`accepted_later`）、驳回（`rejected`）或待核（`pending`）。逐条记录依据、对应原票和责任归属。延后项写明处理阶段，仍影响当前交付的阻断不能延后放行。创作有问题时发给创作者改稿，保留前后稿、改变理由和受影响项目，按新版核验。原判有误时，将具体问题退给原评分岗位，对同一稿件复核，保留原分、复核结果及理由。无需改稿或重判时直接保留原记录。实际操作和回执决定本轮路径。
4. **分别写三个结论。** 单案是否成立取决于各案的事实、表达与必评维度；三案差异取决于各自的主张、创意机制和触点是否真正不同；推荐另写所选方向、理由与取舍。适用必评低于 4 分、关键未知、有据硬退或阻断未解决时留在文案。总监不修改原票，也不以平均分选案。用户采用单独记录。

青屿归档沿用其当时的原文、原票和复核，不补签首读或利用现行流程补评。既有协议可查[双团评审输出契约](../evaluation/双团评审输出契约_v2.md)。
