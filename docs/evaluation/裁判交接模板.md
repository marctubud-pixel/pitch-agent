# 裁判交接模板

用于派发主题、实图、单页与整组评审。先加载 [评估协议](../workflows/评估方法与裁判协议_v1.md)，只采用本阶段分支。主KV加读 [主KV规范](../workflows/主KV视觉总监与横向评审规范.md)。本文件是工作台模板，不是已经发生的评审。

## 总控派发

填写角色、对象/阶段、预期结论范围、评审包路径及哈希、独立性状态、需要的看图/文字能力。模型实际名称未暴露时记录未知。

完整评审包仅给总控。首读另存脱敏子包，不附完整JSON或核验包路径；第二阶段在首读已保存后才另发。当前模板没有自动隔离能力，由总控分文件、分次交接。

- 首读包：随机标记的实际图/文字，首读问题；隐藏方向推荐、作者阐释与旧评价。
- 首读完成后再交核验包：冻结任务、关键点、品牌资产、质量参考；保留已保存首读。
- 单案完成后再派整组包：同版全部候选、两两对照图与参考，按协议第5节交换顺序检查。

完成标准：下列字段齐全；未看的图不得列为已核验；每项关键问题有明确状态。

## 裁判报告

```text
review_id / artifact_id / version / hash:
stage / object_type / role / actual_model:
independence: fresh_context | recheck | author_self_check
method: method_adapted | native_model_run
methods_used: 来源项目、固定版本、实际采用步骤
inputs_seen: 实际图/参考/文字ID、显示分辨率、局部范围
inputs_missing:
calibration: calibrated | uncalibrated（校准记录ID）
calibration_scope: 模型/配置、任务类型、语言、参考与样本集

first_read:
  首个焦点、自然读出的节点/品牌/意思、误读与不确定
  检查模式: model_first_read（非真人限时或眼动测试）

keypoints:
  point_id / visible|contradicted|uncertain / 实图位置 / 理由
text_verification:
  冻结中文原文 / 保留Unicode的实际转写 / 增漏错位置 / 局部核验与未辨清处
diagnostics:
  检查项目 / 实际所见 / 对照依据 / 是否存在问题
scores:
  每个适用维度 / 内部1—5 / 具体依据 / 未核验原因
  官方模型原始分若实际运行另列，附原始单位与运行ID
issues:
  issue_id / rule_id / critical|major|minor
  区域或元素 / 可核验事实 / 对任务影响 / 修改动作
  跨项目重叠观察关联同一个issue_id
conclusion: pass | revise | cannot_assess
  未校准的试评最高为cannot_assess；可交诊断，不能自动签发通过
scope:
unresolved:
next_actions: 最多3—5条优先动作
limits: 模拟判断范围、实测缺口、未核验项
```

## 整组报告补充

```text
same_version_inputs:
pairwise:
  A/B、A/C、B/C分别写：核心机制、构图、空间、美术材质、产品关系、春节表达
order_check:
  展示顺序、交换后结论、相同/取舍/全部退回
counterfactual_checks:
  换节日 / 换品牌 / 换主题（每项实际成立与否及原因）
set_conclusion: pass | revise | cannot_assess
blocking_pairs:
```

## 总控收尾

逐份保留原报告；用户模拟没有明确通过时记录“未签发”，不代签。合并问题后保存责任人、修改版本、重评结论及回归项。通过需要满足协议门槛，拒绝平均分掩盖关键缺口。新稿、旧稿和无效评审均可追溯，正式提案仅展示有效稿。
