# Proposal Workbench 后端完整交付目标

本目标取代此前以局部调研联调或前后端接入为终点的目标。执行到全部后端验收完成，不能在调研、策略或单项导出通过时提前结束。前端定稿后的接入另立目标，不作为本轮开发前置条件。

完成提案工作台的全部后端开发和工程验收，使最终前端可以通过稳定接口使用完整提案生产流程。前端尚未定稿，本目标期间不修改前端源码、版式、组件、字体或交互，也不以旧原型限制后端业务结构。保留已有前端成果，待用户提供最终源码后另行接入。

2026-11-02 交付顺序补充。先保存可在线编辑的结构化提案版本，再从指定版本导出可编辑 PowerPoint。文字和布局修改必须保留旧版、来源身份及变更记录，并使旧审核失效。在线编辑不以桌面 Office 激活为前置条件。原生 Keynote `.key` 另行验证，不能把可打开 PPTX 当作原生导出通过。前端保持冻结，内部编辑服务先行，公开写接口依赖鉴权完成。当前实现与实际验收见 `.scratch/backend-complete-20261031/online-edit-evidence-20261102/RESULT.md`，不以该局部结果替代完整目标。

## 完整业务范围

支持 KV 海报和包装设计。打通以下后端链路，不能以接口存在、单项测试通过或模拟文稿代替完整执行。

Brief 与任务卡 → 多线资料搜集 → 来源与事实核验 → 调研就绪评估 → 三圈依据及候选创意切口 → 策略 → 文案主题 → 视觉参考 → 草图 → 精细视觉及手板 → 全案内容审核 → 排版 → 最终全局审核 → 可编辑 PPT 导出。

1. **项目与任务卡。** 支持项目创建、任务卡提取与修订、来源标记、用户确认、自动和辅助模式、选定人工节点、版本与历史。未确认年龄、购买者或使用者、产品参数时，不擅自补成事实。提供真实的资料输入后端，首版覆盖 PDF、图片及网页链接。
2. **调研与来源。** 由调研负责人分发并行子任务，按任务用途、对象、场景、时间及素材类型限制搜集范围。分别搜集专业报告、品牌产品、同用途竞品、用户及场景资料。跨品类资料有适用理由，行业参考与创意美学参考分开管理。支持来源采集、去重、图片原件、引用、冻结输入、证据支持核验、就绪评估及修订，不把热度或用户偏好当作已认证事实。
3. **策略与交接。** 实现明确的结构化输出，包含核心问题、行业或竞品共识、品牌产品差异、用户及场景需求、三圈交集、候选切口、证据及限制、推导过程和回答初始问题的结论。支持链式及总分总推导。交接必须保留完整原文、来源、实际负责人回执和下游使用限制。
4. **文案。** 文案主题主导视觉。支持稳健延续、放大品牌或产品特征、放大使用氛围或情绪共鸣三个有差异的方向，并推荐一个。保存主题备选、主副文案、创意说明、品牌关联、节日或任务关联、证据及限制。文案总监统筹，独立品牌、用户、传播及文案评审与对应对抗审查参与优化。
5. **视觉。** 每个方向支持多个参考候选，分别评审和比较；参考通过后再生成多个草图构图，选优评审后才进入精绘。视觉总监统筹，独立评分组和对应对抗组参与。保留主 KV 与子海报区分、节日画面关联、方向差异、产品及品牌融入、元素和关键词聚焦规则。支持适合投放场景的 mockup 和包装手板，不把概念效果宣称为生产或实物验证。
6. **评审与迭代。** 文案和视觉保留最多三轮常规优化、原分、原评语、对抗意见、总监裁决和每轮稿件。未达标时按具体维度定位问题，不反复无差别重做。沿用已确认的评分及校准协议，视觉按评审团平均至少 4 星及无有效硬性退回项验收；不把历史平均误差加到分数上，也不把视觉校准结论直接应用于其他任务。参考、草图、精稿使用对应阶段的检查标准。
7. **全案、排版及导出。** 先确认整套内容、措辞和推导通顺，再排版，再做含版式的最终全局审核。后端输出可编辑内容结构、模板、品牌视觉参数、真实资产和图表溯源。通过后端接口或命令生成三套风格不同、内容一致的可编辑 PPT，不能依赖浏览器前端完成导出。文字、图形、图表及主要排版可编辑，图片嵌入文件，无缺图、错误字体替换或溢出。旧稿、过程及评分保留在历史，不进入正式客户提案正文。
8. **资料输入与助手。** 完成提取、任务卡整理及助手的后端能力。助手基于实际项目记录回答，能说明阻塞、下一步和出处，不代替用户确认或编造产物。

## 架构与执行约束

- 采用提案总监、模块负责人、执行子 Agent 三级协作。调研、策略、文案、视觉、排版各有明确职责，独立评审不参与创作。通过配置匹配和替换文字、搜索、视觉理解及图像生成服务，不能写死单一供应商或模型。
- 自动模式按已授权范围运行全流程。辅助模式允许用户勾选人工节点、提交创意或材料、修改和退回。人工决定、模型完成、评审通过、人工采用及阶段放行分别记录；自动模式不伪造人工签字。
- 每次模块交接冻结明确的输入、输出、版本、来源、限制及验收状态。上游变化使相关下游失效，不能只比对产物 ID 而忽略证据、评估、策略或人员绑定变化。
- 支持持久化、并发限制、命令幂等、任务状态、重启恢复、超时、取消及安全对账。未知结果不视为失败后自动重跑。费用和用量未知时如实记录，不填零。缺配置明确报告不可执行，不能返回模拟成功。
- 保留真实来源、原图、版本、评分、失败及调用凭据。限制必须成为下游的有效门禁，不能只归档在报告里。人类偏好不能升级事实或来源真实性。
- 提供稳定、带版本的 HTTP API、可机器校验的数据协议、能力状态、错误码、配置说明和集成示例，供最终前端接入。不得要求组件直接操作数据库或协调后台内部步骤。
- 采用现有代码和已确认业务约定，修复真实缺口，不推倒重建、不搭建重复工作台、不扩展到动画、前端视觉开发或云部署。

## 工程验收

先核对当前源码、开发文档及已有证据，建立全部后端模块的验收矩阵和可重放测试入口。复用已有正确实现，补齐未接通阶段和已发现故障。

使用新临时数据库、本地测试服务和合成供应商，执行完整自动模式及选定人工节点的辅助模式。从输入一直运行到三套 PPT 生成、最终审核及交付记录。至少覆盖一个 KV 案例和一个包装案例，检查产物、引用、真实文件、持久化及重新打开后的状态。

同时测试退回修订、上游版本变化、原件损坏、缺配置、无权限、版本冲突、重复命令、并发、模型失败、未知结果、重启和恢复。用实际持久化记录、请求与响应、生成文件及独立反例证明行为，不能只检查接口返回 200。

已发现的恢复状态缺口和既有失败逐项处理。对确已过时的测试按现行业务合同修正并保留理由，不得通过删除断言、跳过测试或放宽证据与权限门禁获得通过。跨模块关键改动接受独立审查，问题修复后复核。

测试不得修改现有真实项目、评分和历史，不得触发付费模型、生图或其他付费服务，也不得重启现有真实服务进行试验。真实供应商未配置或尚未授权时，完成实际适配器、配置校验和隔离契约测试，明确标记尚未实测的外部能力。后续真实模型和真实品牌的内容质量验收另行授权，不用合成测试冒充。

## 完成标准与交付

交付完整后端源码、可启动服务、接口与数据协议、配置及本地启动说明、模块接入清单、自动和辅助流程的端到端证据、两类案例的隔离完整产物、三套经实际打开和编辑验证的 PPT，以及已同步的开发文档。

只有全部后端业务模块可执行、跨阶段交接与约束验证通过、相关测试和独立审查通过、导出文件真实可用，才能宣布本后端工程目标完成。核心阶段不得以空壳接口或“未接入”替代实现。未配置的供应商和未执行的真实业务验收应明确列出，不能扩大通过结论。

本目标不包含尚未定稿的前端开发与接入。后续收到最终前端后再建立前后端整体验收目标。
