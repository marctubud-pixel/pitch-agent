# 给并行后端开发Agent的执行说明

2026年11月4日。目标是按[后端整合交接版](提案工作台后端开发说明_整合交接版_20261104.md)核对你的已有调研及提案Agent，在独立环境完成相同规格的实现或验证。用户原后端正在开发，定版前端先保留，后端完成并交付后再接入。

## 先核对规格与已有实现

1. 先读整合交接版的范围、覆盖规则和八阶段合同，再读[依据索引](后端交接依据索引_20261104.md)中的专项协议。不要从历史开发日志逐条恢复过期指令。
2. 区分当前静态闭环、长期编辑交付目标和小方后续建议。不要把所有待讨论项加入这次必做，也不要把产品缩成只做调研。
3. 对照你的已有实现列出可复用、缺实现、缺适配、缺配置、缺证据和存在冲突的项。每项关联实际代码、合同及验收依据。
4. 若有本项目代码，复用现有执行器、存储、原件、版本及模块合同，不另建绕过门禁的第二套业务状态。若没有代码，明确你验证的是独立实现，不能报告为本仓库已跑通。

## 隔离开发与验证

使用独立工作目录、数据根、任务身份、输出目录和端口。不要连接、重启、推进、重试、迁移或写入用户当前主案例，也不要共用当前数据库或运行锁。若两Agent位于同一仓库，先分离写入目录和实现所有权，禁止彼此覆盖。

先核对本地合成测试配置和输入合同，用隔离样例证明工程语义；真实模型、实际费用、外部素材采集或当前未授权能力不因收到本包自动启动。对你的现有环境已有用户授权按原授权执行，但不能将它扩展到原主案例。

按依赖拆成可验收的小单元：输入与任务卡、研究核验与交接、策略、主题文案、参考草图与视觉、全案内容冻结、排版及静态终审。先复用有证据的能力，只补实际缺口，不为了整合文档重跑已经可靠覆盖的工作。

自动与辅助模式分别验证。只在有效配置的人工节点等待，明确绑定被看到的版本；不新增逐阶段确认，也不将用户偏好当成事实核验。未知执行结果先对账，不换命令ID重复派发。

## 交付可核对的结果

交付一份“已有、完成、未完成”对照，注明源码与协议身份、输入、隔离环境、实际执行检查、原生回执和覆盖边界。候选、已集成、实际跑通分别列出，工程合成与真实品质分开。

为以后前端接入准备稳定能力矩阵和脱敏样例，覆盖阶段正文、证据与限制、当前及历史稿、允许动作、人工目标、意见与修订、任务及未知状态、媒体身份。按实际接口返回组织，不为符合演示数据而虚构字段或改后端业务。

编辑、保存恢复、确切版本PPTX和真实WorkBot保持后置范围。记录已有实现及限制，不把它们作为当前静态目标的新增前置。预算预留的原要求保留，小方启发的新调度或额度算法仅列候选，不能未经决定实施。

前端本轮不改，也不进行实际联调。待原后端当前约定节点完成并提供稳定交付，再按[已登记待办](../../.scratch/frontend-integration-after-backend-20261104/issues/01-connect-frozen-frontend.md)安排接入。
