# 提案工作台版本沿革与已确认要求

整理日期：2026年11月11日。范围包括本次长对话、项目三份正式规格、现行工作流及相关交付记录。本表用于找回历史与接续，不新增产品要求，不将历史样本或演示界面视为生产验收。

## 1. 先把不同的版本号分开

项目中能找到的正式规格编号是 **v0.1、v0.2、v0.3**。后面没有统一发布的工作台v0.4、v0.5；大部分变化继续追加在v0.3、现行工作流及单次交付目录中。

另外还有四条独立编号线：青屿研究报告R1至R4、调研Skill r1至r7、策略稿r1/r2/r3，以及梦之蓝等案例和视觉评审实验的V号。首页A至E只是设计方向，B是用户选择的层次方案，不能称为五个已发布产品版本。

以下“当前有效”指用户最新决定或仍适用的规格；“已实现”只按注明的本地范围理解。原始发言已在本对话提供；文件记录用于定位和交叉核对，文档日期不等于每条用户发言的精确时间。

## 4. 当前已经确定的产品与协作要求

### 4.1 目标、工作流与负责人

- 输入一个Brief，按统一逻辑完成研究、策略、文案、视觉、排版和交付。内容随任务变化，不能每个案例重造流程和呈现格式。
- 目前首版实际类型为KV和包装。研究规范要能适应海报、TVC及活动等任务；举过这些类型，不等于它们已经全部成为可创建的产品类型。
- 当前前台七阶段：**简报与任务→研究→策略→文案与主题→视觉开发→版式→终审与交付**。
- 人类比稿负责人拥有项目决定权；比稿Agent负责统筹，不是同一个角色。
- 比稿Agent组织板块负责人和执行者，逐阶段检查是否回应同一任务、使用有效上游、逻辑衔接，并在排版前简短核对新矛盾、错版和缺件。
- 不再单设内容审阅页面或负责人。已经说明的演练限制随稿保留，不反复新增相同待办；新的实质问题仍退回所属负责人。
- 排版后保留终审。UI通过、导出成功、单个板块通过，都不能代替整案终审。

来源：[现行工作流](../workflows/提案工作流_现行规则.md)、[比稿Agent](../agents/proposal-director.md)、[词表](../../GLOSSARY.md)。

### 4.2 人类角色与权限

五种人类角色是用户明确提出的；下表是随后落实到本地演示的权限合同，不表示真实账号鉴权已上线。

| 角色 | 当前本地权限合同 |
| --- | --- |
| 比稿负责人 | 编辑全部内容，管理项目和模式，批准阶段及最终交付，可交流。 |
| 工作台使用者 | 编辑需求、研究、方案与视觉内容；不批准阶段、不管理模式，可交流。 |
| 人类视觉负责人 | 编辑视觉及选择版式；只批准视觉阶段，可交流。 |
| 设计师 | 编辑视觉及选择版式；不批准阶段，可交流。 |
| 游客 | 只读，不编辑、不批准、不交流或使用助手。 |

右上角以类似协作文档的方式显示在线成员、姓名及角色，并可查看成员与权限。真人在线与AI任务运行状态必须区分。当前“在线”只统计同一浏览器实际会话，不是真实跨设备团队在线。

自动模式的目标是夜间自行完成整案，完成后通知或提及比稿负责人。通知针对完整可用结果，不能因开始运行、进入最后一阶段或单个岗位完成就发送“整案完成”。站内通知有本地演示；正式后台完成事件、外部消息或艾特、关闭浏览器后的夜间执行仍待接。

来源：[五角色与通知合同](../../.scratch/frontend-ui-optimization-20261108/source/proposal-workbench/docs/TEAM-COLLABORATION.md)。其中旧八阶段及历史暂停措辞受最新规则覆盖。

### 4.3 版本、模型、预算与恢复

- 同一任务、上游依据、稿件、图片、评审和采用要能追溯版本。保留原图、原文、原分、失败与修改，不覆盖成“最新全部通过”。
- 模型按岗位能力替换，不改变已经确认的业务输入输出和核验规则。多个相同模型角色不能自动称为异构验证。
- 独立分支可并行，有依赖的综合、评审和交接要等待必要输入。不能只交摘要而丢失原件、限制及来源。
- 用户可上传PDF、图片、链接、品牌手册、历史方案及实拍等。研究证据与美术参考分开，保留原件和用途；资料已保存不表示模型已经读过或规范已应用。
- 用户参考库与Eagle可以辅助检索、复用与审美校准，不是所有项目的强制依赖，也不是自动审美真值。
- 预算需求为人民币金额硬上限，展示已用、在途预留和剩余，调用次数及轮次辅助控制；超额暂停。真实计费与密钥接入仍未验，不能拿工程模拟成本冒充实付费用。
- 每步保存，恢复复用已完成结果；暂停后不再派新任务。付费调用超时或结果未知先对账，不盲目重试。
- 本地浏览器先行，云端后续。后来追加了团队协作需求，不能继续把早期“仅个人使用”当作排斥团队功能的永久决定。
- 交付目标包括横向逐页提案网页、PDF及后来加入的可编辑PPTX。面向客户展示有效稿件，旧稿、内部评分与过程单独收起；不表示不能展示三个当前有效创意方向。
- 基础编辑目标包括改文字、换图片、调整页面顺序和局部重做，修改前说明影响范围，未受影响部分复用。自由拖拽编辑器曾被后置；在线编辑与保存恢复的当前暂停，不等于这些目标已实现或被永久取消。

来源：[开发说明v0.3](../../多线调研工作台_开发说明_v0.3.md)23.16至23.42及[三级协作](../workflows/任务范围与三级协作.md)。这些是要求，不能一并写成已全部实现。

## 5. 当前明确的UI要求

### 5.1 全站

- 中文桌面版，移除语言切换与手机模式；桌面不同窗口宽度、浅深主题仍要可用。
- 沿用现有蓝色与中性色视觉体系，不随改版更换品牌色。提案作品有自己的颜色，不因UI配色约束被统一改色。
- 保留项目五区域：**概览、提案、资料库、流程与历史、交付**。它们与七阶段是两个层级。
- 页面主层突出当前任务、结果与主要操作；同一信息不反复出现，来源和过程集中展开，必要限制仍要可见。
- 各板块保持统一视觉感，但按阅读任务使用不同版式，不机械地全部做成同一种卡片。
- 图片按真实比例完整显示，重要包装和样机可看清、可放大，不拉伸或为凑卡片裁掉主体。
- 每轮页面完成后用`ui-review`检查实际界面。工程构建、业务评审和UI审核分别记录。

来源：[中文桌面规格](../../.scratch/frontend-ui-optimization-20261108/source/proposal-workbench/docs/DESKTOP-CN.md)及[现行工作流](../workflows/提案工作流_现行规则.md)。原DESIGN-SPEC里的多语言、手机、八阶段是历史规则。

### 5.2 首页最终选定的组合

### 5.3 新建提案

- 增加“提案汇报时间”。去掉“选填”等冗余说明，不等于用户决定必须填写；当前仍允许留空。
- 任务卡只出现一次，不重复写“核对任务卡”。普通字段不反复堆“来源与说明”，保留集中查看原文。
- 支持上传品牌资料、视觉手册、格式规范及补充文件，作为后续参考。原件保存与正式模型引用接线分开。
- 视觉上呼应首页蓝色与雾灰白，避免满页纯白、无层次。
- 新建页长文本框默认三行、等高对齐，取消拖拽调整大小，超出内容在框内滚动。

### 5.4 项目页与简报任务卡

- 摘要与实际已填写内容一致，确认入口放首屏，显示汇报时间与确认负责人。任务卡只有一份。
- 当前主字段为六项：**项目名称、提案类型、品牌或产品、背景、目标受众、交付内容**。提案类型紧跟项目名，手动选择；首版实际支持KV与包装。
- “具体交付要求”改为“交付内容”。业务目标、预算等旧值退出当前可见字段，不删除历史数据。
- 工作方式只保留自动和协作，配简单图标。“更多信息”仅保留调研问题、限制条件及一份品牌与参考资料。
- 删除当前卡里的重复参考、原始材料面板等入口；原件、原文和历史仍在保存体系里。
- 阶段想法放右侧。使用“版本记录”，不再叫“修订记录”；各版本显示备注、真实修改人及确认状态，帮助协作者知道要求改过。
- 有真实关联时才显示留言已反映到哪个版本，不自动编造“已更新”或历史作者。
- 项目任务页长文本框加高到五行，品牌与背景框底部对齐，继续内部滚动、禁拖动。它与新建页三行设置不同。
- 未确认时按钮为“确认简报”，已确认后为“更新简报”。更新直接修改当前卡；已确认版本变更先审阅，再形成待确认新版。
- “进入下一阶段”放在首屏，不藏在底部，也不再叫“查看下一阶段”。它是导航，不能代替业务确认与放行。

## 6. 各制作板块的版本与最终要求

### 6.1 研究

研究内容演进为：首版结果页→报告修订2→六图版→报告修订3→报告修订4→版式工坊呈现。

| 节点 | 主要要求与取舍 |
| --- | --- |
| 首版结果页 | 行业与市场、人群、竞品、产品、研究结论五板块；每块先直接结论，再数据、图表和具体案例。 |

当前调研Skill是r7。报告修订4原研究采用的是r6；r7增加稳定模板和交接，并不意味着已经重新搜集了一轮资料。

研究的长期要求：

- 先问这次研究为了什么设计判断，再决定问题。四维是行业与市场、人群、竞争、产品与品牌；输出末块为研究结论。
- 包装研究回答包装在寻找、识别、理解和选择中的作用；KV/海报研究注意、信息与记忆；TVC研究观看、叙事、情绪与品牌关联。不把同一套包装问题套给所有媒介。
- 行业要回答需求和竞争如何变化，不能拿SKU增多直接证明需求增长。指标写清年份、单位、口径和同比等比较基准。
- 人群先解释是谁、生活、关注、偏好和变化，再连接场景及包装或媒介作用，不能只有年龄或只谈价格。
- 竞品先有总体地图、价格或任务可比组，再看重点品牌、共性、差异及例外。不能每个品牌各放一张图而不总结。
- 包装参考优先清晰、放大的单品本体，不能用海报里看不清的小瓶替代包装细读。
- 优先合适的行业及消费洞察报告；仍检查市场、人群、年份、样本、渠道及统计口径。
- 中国任务中，海外资料可标注为背景或视觉参照，不能直接证明中国消费者偏好。
- 可以找强相关邻近品类、同年龄人群和跨行业媒介情景，但负责人必须解释可参考之处、差异与适用边界；不能反推成因果证明。
- 每块结论直接回答任务问题，末块综合需求、竞争回应、产品条件及矛盾。具体定位、创意取舍交给策略，不在研究中提前写完。
- 图表、图片为主，详细分析、方法、核验与来源展开；一板块不限定只有一图。图表保留可改颜色、数据和排版的结构，不做成唯一的整张图片。
- 页面取消逐图下载，只在底部保留下载调研报告。人群场景可以用生成图辅助，但须明确标为示意。
- 独立事实核验与读者质疑分开。关键本地依据补查仍不足，就交已有结论与缺口，保持“研究待补”，不能用解释到对方满意代替补证。

两份包装PDF是歪马精酿与君乐宝，用来借鉴分析方法，不继承它们的旧数据、具体创意或固定目录。

### 6.2 策略

策略先经历r1、r2、r3方法和稿件。r2中的“借个桌角，开瓶喝茶”等被用户明确退回：把具体文案写进策略、洞察浅、卖点换任何品牌仍成立，审查也没有证明策略质量。之后加入虎跑泉用水设定重推r3，但用户最终认为要求太多，明确改为简化负责人要求。

**当前不再强制使用策略Skill或固定多轮评分。** 只保留两项基础要求：依据研究，结合产品特质与目标用户找到交叉点；说明优先放大什么及为什么。基础核验仍要成立，缺依据标明，不补成事实。

页面为两三页、三个板块：**研究结论、方向交叉点、策略发力点**。第二页采用三环或适当关系图，交集连到右侧结论；沿用研究版式体系。具体主题、主副文及画面留给下游，不在策略里提前写。

新增的民生银行亲子金融、美的视觉、洋河微分子三份PDF，与前两份包装案共同提供推导方法参照，不是五套必须照抄的策略模板。

青屿目前的虎跑泉用水是用户提供的演练产品设定，不等于已验证供应链、唯一性或消费者效果。

### 6.3 文案与主题

简单三方向稿后来被完整两轮创作替代。稳定要求是从策略拉开三个实质不同的创意方向，不是同一个意思换三句表达。

文案、品牌、目标用户模拟、传播四岗分别评价并提出问题；对应异议检查和独立总监裁定与作者分开，保留原分、修改前后及复核。不能由总监修改原评分，也不能把模拟用户评价称为真实消费者认可。

页面主层保留方向、主副文及推荐理由；具体推导、评分、异议和修改记录点击展开。已明确盲审的输入不得夹带作者推荐或其他裁判意见；青屿这次正式评分读过作者回应，因此不能称为全程盲评。

当前青屿三方向是：**两张名片、一口到虎跑、看见虎跑，想起你**。“两张名片”是总监建议优先讨论，不是用户已经选定，也不是包装图效果通过。

### 6.4 视觉开发

流程采用统一视觉负责人Skill，版本1.0.0。负责人安排创作，独立评分、对应对抗及裁定在创作链之外。

顺序为：核对同版任务与方向→找多候选实际参考→独立适用性评审→冻结主辅参考与借鉴边界→每方向三个实质不同的构图草图→结构选优与深化→成稿复核→三方向横向比较与交接。参考不逐张等待用户人工确认，但独立评审不能取消。

现行准入区别：参考必评适用项逐项不低于4；草图及成稿由指定四岗整体原票等权平均不低于4，缺票不能缩小分母，关键未知与成立硬伤另行阻断。常规最多三次修改，达标可早停，超限暂停；旧“额外专项三次”不默认启用。

固定页面语言包括三方向切换、当前稿、参考与草图、三方向对照；参考扇面、三纸页草图文件夹、左主图右文案评审、版本位置及可放大的样机。用户退回过“紧凑空稿＋常驻规范栏”，因此恢复大图、保留主区宽度，规范与版本默认收起，协作前置，减少重复空态和评分空壳。

当前已补3主图、9独立构图探索、3正侧背整板样机，另保留6件真实包装参考。它们是设计试稿；有图片不等于参考、草图和精修的正式业务评审闭环都已通过，更不是印前生产稿。

### 6.5 内容检查、排版与终审

独立内容审阅做过一轮页面与审读，后来被用户明确取消。它不是“做完后默认通过”，而是前台退役；旧问题、原文、意见和回执保留，检查职责归比稿Agent。

研究阶段就使用后续PPT可复用的图版，整案排版沿用已接入的Deck Studio 1.7和已确认版式。依据每页主旨选页型，不是每次调研重新换格式，也不是所有页面同一骨架换皮；内容多时拆页，不能不断缩小字。

预览与PPTX使用同一页面对象。文字、图表、关系形状与独立图片分开，图片等比，比较页同尺度，页序连续；详细来源放备注或附录。原包包含的全部模板和变体，不代表本工作台已经逐一适配。
