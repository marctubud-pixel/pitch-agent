# 视觉开发负责人

版本 **1.9.0**。本 Skill 是可复用的人工编排规范。项目实际采用路径与版本由项目入口指定，候选保存和人工采用各有回执。

视觉负责人位于提案总监与执行者之间，负责输入与授权、任务拆解、搜索与绘制分派、候选选优、修改整合、版本交接。独立评分、四对应对抗和独立裁定均在创作链外。创作负责人不能自签通过；总监只能合并原票，不能改分或豁免有证硬伤。用户模拟不是真实消费者研究，模拟裁定不是真客户批准，同模型多 Agent 不等于异构验证。

## 执行顺序

1. **冻结工作包。** 核对任务、范围、Brief、主题、文案、输入版本、实际图像、来源、授权终点、模式、人工节点、预算和停止条件。缺失列为待核，历史通过不得替代当前依据。按[记录协议](references/records.md)落盘，完成条件是来源与版本可核。
2. **读取任务附录。** 包装任务读[包装](references/packaging.md)，主 KV 或海报任务读[KV](references/kv.md)。将当前方向的核心主张、品牌/节点依据、画面主角、视觉问题、关键限制和与另两案的差异写进搜索卡。默认三个探索岗位为稳健延续、产品特征放大、用户氛围/情绪放大，具体主题沿用当前确认输入。
3. **收集并保留。** 分派依赖已满足的独立执行任务；共享输入只读，各自写产物。每方向收集多个可查看候选，按方向任务确定主参考；辅助逐张说明借鉴位置、作用和落在本案的画法，重复或缺乏依据就留缺。集中去重，保存原图、图源、具体借鉴位置、转译假设、禁止照搬及缺口。只有 intake 授权时，完成候选与缺口后停止，主/辅/备用保持未选定。
4. **独立评审。** 读[阶段规则](references/stage-review.md)。草图先盲读原图并封存原话，再揭示任务依据；出现影响主张的误读时定位、局部改稿、另存原件，换未见旧稿的新评审盲读复核。进入正式评分时，向裁判提供必要任务事实、用途卡和实际图片，不提供作者推荐、旧分或其他裁判意见。四岗先独立评，四对应对抗先独立找问题再核断言，独立裁定保留采纳/驳回理由。所有记录绑定任务、实际图片哈希、输入与 Skill 版本。完成条件是原票齐全且关键未知与有据硬伤明确处理。
5. **按准入交接。** 参考先审适用性，适用必评逐项 ≥4，不取平均。草图/成稿四岗各一票整体分，未舍入均分 ≥4；缺票不能缩小分母。四对应对抗不评分。关键未知与有证硬伤独立阻断。每个进入视觉开发的方向，按下方「借三改二」用同一主参考直接生成三张主视觉。四岗看实际图片独立打整体分，四对应对抗核票，独立总监裁定。仅在四票齐全、未舍入均分 ≥4、无成立硬伤和关键未知的候选中推荐最高稿。同分按总监记录的取舍决定。全批未达标则留在视觉开发，保留原图及原票，根据具体问题修订；采用与推荐分开记录。已有草图保留作对照。
包装主视觉另执行[包装任务的盲读、并排与四岗评分协议](references/packaging.md)。每次先封存匿名单图读法，再提供简报与同类原图。海报与 KV 按[海报附录](references/kv.md)交接上图原句和读图记录。定点修改一张时保留对照稿，记录修改前后的证据。

6. **整合或暂停。** 常规最多三次修改，达标提前结束；达到修改或预算上限则暂停受影响方向，列最佳现有稿和未决项。旧额外三次专项不自动启用。每次改图另存新版本并重新取票；上游改变使受影响通过记录待复核，原图、原票、原裁定及发生时间保留。
7. **交付检查点。** 自动模式也止于授权终点。辅助模式在配置节点等待明确人工决定，超时不等于同意；已有明确执行授权不重复询问。保留用户指定采用及异议，它不能伪装成评审通过。交付注明提案概念稿或投放成品、实际完成、未决项与下一步所需授权。

## 按策略搜集与精选参考图

先从当前策略和方向原稿写出一句“观众要理解什么”。分别搜索同类载体的创意案例、实现这个创意所需的局部手法或现场资料。优先核对品牌官网、设计机构作品集和设计奖项原页，必要时跨行业、中英文检索。Eagle 可按方向匹配补充已有素材，星级不限，入库按任务要求执行。

打开原图，先记焦点、载体、文字层级、颜色、材质及可见细节，再比较同一用途下哪张表达更清楚。相同原图、转载和机制相同的系列角度只留最清楚的一张。记录出处、主辅用途、借鉴位置、本项目的转译办法、禁止照搬处以及竞争候选的留退理由。按原参考用途协议复核适用项，逐项达到 4 分后准入。看不清的局部标为未知；缺能承接方向的主图时回去补搜。

青屿「一口到虎跑」的策略是放大泡茶用水，方向借喝茶表达抵达虎跑。试选中，地方风土茶提供“把地点装进一份茶”的主创意，瓶装茶案例和泉池实景分别补信息层级与场所特征。Eagle 图提供茶汤与冷灰石材的处理。用户在两组各一张包装试稿中偏好策略精选组。早先修正水流落点只解决了一张草图的误读。其他项目按各自的策略重新定搜索任务。

## 借三改二

看主参考的五项是配色、布局、景别、笔法和字体。布局包括标题位置、留白以及背景和前景的关系。景别说明观众看见多大范围。笔法看线条、切边、笔触。字体看字形和字重。沿用能表达本案的整体美术风格，地景、人物、图形和文字由本案重新创作。需要背景时，先写明它怎样衬托前景动作，再画出本案完整场景。

| 候选 | 借 | 改 |
| --- | --- | --- |
| 第一张 | 布局、景别、笔法 | 配色、字体 |
| 第二张 | 配色、笔法、字体 | 布局、景别 |
| 第三张 | 配色、布局、景别 | 笔法、字体 |

每张用同一主参考原图和该张提示词直接出图。辅助图的动作、场景或材质用文字交接。品牌原件和返修原稿按各自用途随输入传递。常规出图直接从参考和文案开始，已有草图可按专项任务验证。回执记录实际附件与每张借、改的项目。保存主参考和新稿，供并排核对两处变化、背景、动作和文案。

桌面将文字 API 写成的制图内容和实际附件交给生图 API。记录文字模型、请求编号、实际提示词和生图回执。单独委托海报或 KV 时先核读主参考，再按[海报附录](references/kv.md)写借改指令并核对成图。包装出图及品牌岗的印字核验按[包装附录](references/packaging.md)执行。

## 可运行检查

按[记录协议](references/records.md)执行 `node scripts/check-stage.mjs <work-package.json>`。脚本只读本地证据并输出 `decision/reasons`，不生成图片、不写业务数据库、不调付费服务。它校验文件哈希、版本、缺票、角色分离、授权、确认与轮次，不能证明人真的看过图、身份真实或审美有效。必要图片或原票看不到时应停止并补证；脚本通过也必须读实际图片和独立判断。

当次任务的范围写入独立调用记录并绑定授权来源；本 Skill 的通用能力不扩大该次授权。intake 和资料整理仅封存真实候选与缺口，无需尚未发生的美学原票；请求阶段准入时才要求对应独立记录。
