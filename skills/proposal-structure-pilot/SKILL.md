# 客户提案逐页编稿

比稿 Agent 组织整案编稿，各负责人提供已交接的原件。先回答“客户今天要解决什么、看完要决定什么”，再按[逐页内容库](references/page-library.json)生成页序。页库中的标题是写作者的提示，正式提案应换成本案判断或作品名。每条记录规定要填什么、要拿什么给客户看、怎样检查，具体布局留给[排版方法](../proposal-layout-pilot/SKILL.md)。

## 1. 登记任务，再生成空稿

从当前 Brief 取提案类型、客户要作的决定、实际方向名、SKU／画幅、投放或售卖触点、额外委托、项目状态。取同版的研究、策略、主题、设计原件、有效评审和展示授权。在编稿记录里列清所用版本。按约定对外展示的成熟方向通常为三案；两案用于明确要求展示两案的任务。历史案沿用原方向，不硬套新命名。三案任务暂时只有两案成稿时，把缺的那案记在编稿记录，不能据“两案也能生成”当作放行。

在仓库根目录运行以下命令。输出默认是可直接填写的 Markdown，加 `--format json` 可保留逐页字段。只生成页目和待填位，脚本不读取客户数据或调用模型。

```sh
python3 skills/proposal-structure-pilot/scripts/build_outline.py --kind packaging --directions 方向A 方向B 方向C
python3 skills/proposal-structure-pilot/scripts/build_outline.py --kind kv --directions 方向A 方向B --include adaptation motion activation
```

## 2. 按客户翻阅顺序填页

| 页段 | 每一页解决的问题 |
|---|---|
| 开场，3 页 | ① 封面写品牌、项目名和载体 ② 目录列本稿章节和实际起页 ③ 客户的问题、委托和待决定事项。 |
| 研究，基础 5 页 | ① 行业现象 ② 品牌已有资产 ③ 同任务竞品的作品对照 ④ 人群和决策场景 ⑤ 产品事实。对客从行业、品牌与竞争、人群、产品四个角度讲；品牌现貌与竞品原图分开给客户看。取材仍按研究岗原有四线：行业与市场、人群、竞争、产品与品牌。每页给可见材料、解释及一句对本案的判断。 |
| 策略，基础 3 页 | ① 综合研究发现，同时完成研究小结 ② 研究机会、产品事实与人群需要怎样相交，为什么没选另一个可行主张 ③ 一句话优先放大什么，作品上怎样看出做到了。可将前两页合讲，三个问题均保留。 |
| 方向总览，1 页 | 用一行讲清每个思路。客户能在看大图前区分各案，再按同样的次序逐案看作品。 |
| 每个 KV 方向，基础 5 页 | ① 主题与创意解释 ② 完整主视觉 ③ 用同稿局部解释构图或视觉选择 ④ 放进第一媒介看 ⑤ 换个触点看。委托多尺寸时另给完整第二画幅。 |
| 每个包装方向，基础 6 页 | ① 方向与包装创意 ② 完整正面 ③ 侧背／展开与结构 ④ 信息、图形或工艺细节 ⑤ 同类货架／真实售卖条件 ⑥ 电商缩图、手持等第二触点。系列任务另给同案 SKU 全貌。 |
| 收尾，基础 3 页 | ① 各案同尺度并排，说明推荐与取舍 ② 本次要客户定什么、还需补什么才能制作 ③ 封底。委托或讨论营销延展时，在比较后、决定前增加一页。 |

## 3. 何时增页、减页或补资料

- **研究的篇幅随证据变化。** 行业有两种不可混用的口径，拆页标来源、时间、范围和单位。人群画像与购物场景各能支持一个决策时，分别给页；空泛年龄段和摆拍不能代替行为依据。场景照片注出处，AI 示意标明身份，另列支持行为判断的证据。产品事实、潜在利益和消费偏好分别取证。
- **按任务启用作品页。** `adaptation` 用于 KV 第二画幅成案，`process` 用于解释关键选择的真实制作过程，`motion` 用于动效或分镜，三者分别占页。`series` 用于包装的同方向多 SKU。`activation` 用于有承接对象的活动或品牌传播设想，全案一页。缺视频只写分镜／待补；缺实物打样只写渲染与待核工艺。有原件但与客户决定无关的过程可留附录。
- **同个委托用同把尺。** 各案用同样的核心页位、比较尺度与真实触点。客户明确只有一个渠道时，用 `--single-touchpoint` 给各案一同裁减第二触点。生成器的 `--include` 会给每案加入所选的方向页；若只有一案适用，编稿时仅在那案保留可选页，注明材料及增删缘由。删页、插页、拆页后重算目录和所有引用。同案内的三个候选与三条创意方向分别处理。
- **先确定所提的是哪类作品。** 首版页库覆盖包装与 KV。独立 TVC、IP 表情、整场活动有独立交付结构。在复合委托中列出各自交付物，六案的相关页可作参考；遇到整案以这些载体为主，另编经过核对的专项页序。不能用一页动效或活动设想代表整份专项提案。
- **指定旧案时先对原页。** 按原件物理页码记录页用途、主体、本案对应页和增删理由。六案的页段与案例边界见[原案索引](references/cases.md)。封面和目录是本方法的固定开场，即便参考案直接进入市场分析。资格、团队、历史案例和执行报价只随委托要求入稿。

## 4. 填完后按页交接

每页保留实例标识、页码、客户可见标题、一句判断／要展示的主体、材料出处与版本、状态。缺件另记影响、负责人及补查或复验方式。必要的拆分可在原实例下增加子页标识，保留原页对应关系。客户只看到影响决定的限制及必要的图源，内部评审过程留在原记录。

顺着全文检查三次连接：从问题能翻到支持它的证据；从证据能解释为什么优先选这个策略；从策略能翻到对应作品，并在购买或观看触点上看到解决办法。演练可用“待验证”陈述读出仍缺的依据；影响正式策略或对外主张成立的关键缺口退原负责人补齐。资料足够才把相应方向、同版作品与逐页稿交给排版。排版前沿用现有比稿简核；最终采用根据人类实际决定登记。

[编稿与排版的交接及流程图](../../docs/plans/客户提案结构与排版交接_试行.md)记录两者职责和当前工作台接入范围。

## 在夜航绑定补充原图

系统自动取本版研究、策略、文案及采用的主视觉。要放入已备好的侧背图、媒介样机或场景图，可把 PNG／JPEG 和 UTF-8 的 `逐页材料.md` 作为项目附件一并提供。每节以完整页实例为标题，逐张写图片的原文件名。方向页用“对应主稿”写本轮工作台采用的主图文件名。例中页实例、方向和文件名均需替换为本案实际值：

```md
## packaging/pack-shelf/青石
身份：售卖场景模拟
图片：青石冷柜.jpg
来源：本案本轮冷柜陈列模拟稿
对应主稿：本轮已采用的青石主视觉.png
说明：同柜陈列时品牌的识别位置
```

仅列已启用页位。品牌、竞品和人群页分别用“品牌原图”“同类原图”“实景照片／AI场景示意”，须注明具体出处和图的含义。包装补充视图的身份可用“同版包装视图”“同版包装细节”“同版系列图”“售卖现场实拍／售卖场景模拟”“购买触点样机”；KV 可用“制作过程记录”“动效关键帧／分镜设想”“第二画幅成稿”“媒介样机”。活动页用“活动设想”，另填“承接方向”和该方向的“对应主稿”。斜线表示两种可选身份，每次只填一种。章节和字段只解释材料的用途；真实出处及授权由提供人负责。方向或版本对不上、文件缺失、重复填同一页时，工作台会记录未绑定原因。补充图只用于指定页，研究判断、策略、主标题和采用的主视觉分别取其本版原记录。

编稿脚本从[页面库](references/page-library.json)读取 31 类页面的模板类型和变体，按 `instance_id` 把模板、客户标题、逐页内容、原始素材身份一并交给排版。行业页交可回指同一来源的时期、数值与单位，竞品页交对象和对应观察，人群页交实际使用或购买情境，产品页交已知属性与取值。缺材料时记录缺口，模板字段不构成补写事实的依据。实际分页与版型写回逐页稿。
