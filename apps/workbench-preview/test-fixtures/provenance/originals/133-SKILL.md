# 视觉开发负责人

版本 **1.0.0**。本 Skill 是可复用的人工编排规范，不代表自动业务调度已接通。项目实际采用路径和版本由项目入口指定；保存候选不等于采用，也不自动安装全局。

视觉负责人位于提案总监与执行者之间，负责输入与授权、任务拆解、搜索与绘制分派、候选选优、修改整合、版本交接。独立评分、四对应对抗和独立裁定均在创作链外。创作负责人不能自签通过；总监只能合并原票，不能改分或豁免有证硬伤。用户模拟不是真实消费者研究，模拟裁定不是真客户批准，同模型多 Agent 不等于异构验证。

## 执行顺序

1. **冻结工作包。** 核对任务、范围、Brief、主题、文案、输入版本、实际图像、来源、授权终点、模式、人工节点、预算和停止条件。缺失列为待核，历史通过不得替代当前依据。按[记录协议](references/records.md)落盘，完成条件是来源与版本可核。
2. **读取任务附录。** 包装任务读[包装](references/packaging.md)，主 KV 或海报任务读[KV](references/kv.md)。将当前方向的核心主张、品牌/节点依据、画面主角、视觉问题、关键限制和与另两案的差异写进搜索卡。默认三个探索岗位为稳健延续、产品特征放大、用户氛围/情绪放大，具体主题沿用当前确认输入。
3. **收集并保留。** 分派依赖已满足的独立执行任务；共享输入只读，各自写产物。每方向收集多个可查看候选，集中去重，保存原图、图源、具体借鉴位置、转译假设、禁止照搬及缺口。只有 intake 授权时，完成候选与缺口后停止，主/辅/备用保持未选定。
4. **独立评审。** 读[阶段规则](references/stage-review.md)。向裁判提供必要任务事实、用途卡和实际图片，不提供作者推荐、旧分或其他裁判意见。四岗先独立评，四对应对抗先独立找问题再核断言，独立裁定保留采纳/驳回理由。所有记录绑定任务、实际图片哈希、输入与 Skill 版本。完成条件是原票齐全且关键未知与有据硬伤明确处理。
5. **按准入交接。** 参考先审适用性，适用必评逐项 ≥4，不取平均。草图/成稿四岗各一票整体分，未舍入均分 ≥4；缺票不能缩小分母。四对应对抗不评分。关键未知与有证硬伤独立阻断。参考冻结主/辅/备用和借鉴边界后，才可在授权内进入草图。每个方向形成三个视觉机制或构图关系实质不同的草图，不以换左右位置凑数；保留所有候选与原评，选择评分较高且达标的稿件，最高分仍未达标则停止该方向。结构通过只允许深化，成稿仍需整体复核与三方向差异检查。
6. **整合或暂停。** 常规最多三次修改，达标提前结束；达到修改或预算上限则暂停受影响方向，列最佳现有稿和未决项。旧额外三次专项不自动启用。每次改图另存新版本并重新取票；上游改变使受影响通过记录待复核，原图、原票、原裁定及发生时间保留。
7. **交付检查点。** 自动模式也止于授权终点。辅助模式在配置节点等待明确人工决定，超时不等于同意；已有明确执行授权不重复询问。保留用户指定采用及异议，它不能伪装成评审通过。交付注明提案概念稿或投放成品、实际完成、未决项与下一步所需授权。

## 可运行检查

按[记录协议](references/records.md)执行 `node scripts/check-stage.mjs <work-package.json>`。脚本只读本地证据并输出 `decision/reasons`，不生成图片、不写业务数据库、不调付费服务。它校验文件哈希、版本、缺票、角色分离、授权、确认与轮次，不能证明人真的看过图、身份真实或审美有效。必要图片或原票看不到时应停止并补证；脚本通过也必须读实际图片和独立判断。

当次任务的范围写入独立调用记录并绑定授权来源；本 Skill 的通用能力不扩大该次授权。intake 和资料整理仅封存真实候选与缺口，无需尚未发生的美学原票；请求阶段准入时才要求对应独立记录。
